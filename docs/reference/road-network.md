# Road network

Reference for the offline road-network stack. Read the code when this and the code disagree.

## walk-cost.js — `window.WalkCost`
Crossing-penalty classification + cost math. Pure (no turf/DOM/Map/App), same engine-namespace convention as `window.ConnectorGraph`/`window.Travelshed`/`window.TPI`; golden-tested in `test/cases/walk-cost.mjs` (see `docs/archive/walkshed-bands-and-crossing-penalties-plan.md`).
- `roadTier(hwy)` → `"major"` (primary/secondary + `_link`) or `"minor"` (everything else — `tertiary` deliberately minor, usually an unsignalized collector; unknown/absent → minor).
- `nodeTier(hwyList)` → `"major"`/`"minor"`/`null`; `null` when fewer than 3 edges meet (shape point / dead end), which keeps the penalty off most vertices.
- `penaltyKm(tier, {majorSec, minorSec, speedKmh})` → `speedKmh * sec / 3600` (constant wall-clock delay regardless of speed); 0 for null tier or zero/absent sec/speed.
- Node-uniform, not turn-aware — deliberate approximation (over-charges travel along an arterial). Motorway/trunk never reach it (already `pedBlocked`).

## network-store.js — `App.networkStore`
IndexedDB cache for the downloaded network (too large for `localStorage`, expensive to re-fetch from Overpass). DB `mat-network-cache`, store `networks`, keyed by `id`, `savedAt` index. Record: `{ id, savedAt, source: "overpass"|"file", label, featureCount, extent (Feature<Polygon>|null), geojson (JSON string) }`.
- `App.networkStore.supported()` → bool (false e.g. in some private modes; callers degrade to "no cache").
- `App.networkStore.save(record)` → `Promise<boolean>`, never rejects. Writes, then prunes oldest-first to `MAX_ENTRIES`; a failed write (quota) retries once after dropping every OTHER network, then gives up quietly.
- `App.networkStore.latest()` → `Promise<record|null>`, never rejects. Reads the `savedAt` key list first, fetches only the winner (others' geojson never deserialized).
- `App.networkStore.findCovering(extent)` → `Promise<record|null>`, never rejects. `extent` is a `[w,s,e,n]` bbox or a GeoJSON Feature. Returns the **newest** stored network whose download extent contains it. Candidates are picked from the keys alone: an Overpass id `bbox:w,s,e,n` (3 decimals) is shrunk by the 0.0005° rounding so it never overstates coverage, then only the winner is fetched and its stored `extent` checked exactly (stored extents are axis-aligned rectangles, so bbox containment is exact). File imports (`file:` ids, no extent) never match.
- `App.networkStore.clear()` → `Promise<boolean>`; called by `clearRoadNetwork()`.
- `App.networkStore.MAX_ENTRIES` = 3.

Everything is an optimization: failures are swallowed and callers fall back to a fresh download.

**Rule — `_withStore(mode, fn)`:** an IndexedDB transaction deactivates when control returns to the event loop, so `await`ing one request then touching the store throws `TransactionInactiveError` when the main thread is busy (i.e. page startup, exactly when this store is read). `fn` must issue requests synchronously or from another request's `onsuccess`, never after an `await`. Do not copy the `_idbTx`/`await` shape of the Recent Projects store in `cache.js`.

## road-network.js
Overpass/file import → graph → Dijkstra. Graph weights are **km**; `budgetKm = walkSpeedKmh * minutes / 60` (Walkshed's UI is mph and converts first).

**Public API:** `App.roadNetworkLoaded()` (bool), `roadNetworkEpoch()` (int, bumped on every (re)build/clear — epoch-keyed module caches use it), `findLocalRoute(waypoints)` (driving), `fetchRoadNetwork()`, `loadRoadNetworkFromFile(file)`, `exportRoadNetwork()`, `unloadRoadNetwork()`, `clearRoadNetwork()`, `restoreNetworkCovering(extentPolygon)`, `clearRoadDownloadArea()` (outline only, graph kept — Layers panel), `restoreCachedNetwork()`, `computeWalkshed`, `computeWalkCostMap`, `contourSamples`, `nodeKeyToCoord`, `snapWalk`, `getRoadDownloadExtent`, `fetchRoadNetworkForExtent`, `App.getWalkNetworkSegments()`, `App.setNetworkConnectors`, `App.getLastConnectorOverlayReport`, `App.setExcludedWays`.

**Rebuild choke point.** Private `rebuildNetwork()` = `buildGraph(_roadGeoJSON)` → `applyConnectorOverlay()` → one `_networkEpoch++`. Every base load (`fetchNetworkForBounds`/`loadRoadNetworkFromFile`), connector change and exclusion change routes through it, so connectors/exclusions are never merged into `_roadGeoJSON` and re-apply automatically after a re-download. `updateUI()` is the single choke point for map-side refresh (download outline, `App.refreshWalkNetworkLayer()`, `App.refreshSidewalkCoverageLayer()`); `rebuildNetwork()` alone does NOT refresh map sources.

**Download.** `fetchRoadNetwork()` fetches the current view expanded ×1.5 per side (`turf.transformScale`), vehicle roads plus `living_street|pedestrian|footway|path|steps|cycleway`, capturing `foot`; `window.confirm` above `MAX_AREA_WARN_KM2` (2000 km²). Extent recorded as `_downloadedBboxPolygon`, drawn as a dashed `#c026d3` outline (`road-dl-area` / `road-dl-area-line`, Layers "Road download area"); file imports have no outline. `fetchRoadNetworkForExtent(extentPolygon)` → `Promise<boolean>` downloads a caller-supplied extent (same helper), replacing the network and bumping the epoch. `getRoadDownloadExtent()` → `Feature<Polygon>|null`. The parse also captures `sidewalk`, `footway`, `crossing` and `wayId` (parse-side only; `out geom;` already returns them). These go on `_segmentIndex` entries, deliberately not on graph edge objects (hot path, allocated twice per segment).

**Class-aware traversal.** `buildGraph()` tags each edge/segment `pedBlocked`/`carBlocked` via `isPedForbidden(hwy, foot)` (motorway/trunk + `_link`) / `isCarForbidden(hwy)` (footway/path/steps/pedestrian/cycleway); explicit `foot=yes/designated/permissive`/`foot=no` override. Walk flood skips `pedBlocked`, driving `dijkstra` skips `carBlocked`, `snapToNetwork(lngLat, mode)` filters per mode (`"walk"`/`"drive"`, absent = no filter). One download, two interpretations.

**User-excluded streets.** `buildGraph()` ORs the private `_excludedWays` Set into `pedBlocked` and records `userExcluded` separately, so the flood skips it but segments/`connector-graph.js` can still tell it apart; `carBlocked` untouched. **`App.setExcludedWays(ids)` is the ONLY write path**: sets the Set, writes `App.networkSettings.excludedWayIds`, `App.cache.save()`, `rebuildNetwork()`, then `updateUI()` (without `updateUI()` an exclusion changed routing but not the map — a past bug). `collectCandidateSegments()` passes `userExcluded` so connectors can still weld to excluded streets (see connector-graph.js).

**Snapping.** `snapToNetwork` queries a uniform grid `_segGrid` (≈0.5 km cells, built in `buildGraph()`, 3×3 neighborhood covers `SNAP_MAX_KM` = 0.5 km) with inline equirectangular `nearestOnSegmentKm` math — the old whole-network turf scan cost 1–3 s/call and was the real Transit Travelshed bottleneck. Cleared in `unloadRoadNetwork()`.

**Boundary shape (`shape`).** Every walk polygon is a travel-time contour (described next); `computeWalkshed(..., {shape})` takes the settings object from `App.walkShapeFor()` and reads it from there when `shape` is absent. The original concave-hull boundary (later "Classic"/"Simplified"), its Hull detail setting and `App.polygonizeNodeSet` were removed; what it did, why, and how to restore it: `docs/archive/walkshed-simplified-shape.md`.
**Contour tracing.** `computeWalkshed` builds a travel-time surface: `App.contourSamples(costs, maxCost, stepKm, costPerKm, partialEdges)` turns a nodeKey→cost map (Map or object) into `[[lng, lat, cost]]` samples (every reached node, plus a point every `stepKm` along each non-pedBlocked segment, cost `min(cA + t, cB + (L − t))`; `partialEdges` also samples segments with only one end reached, which is what carries the edge partway down the last block). `WalkShape.contour(samples, budgets, {gridKm, offStreetKm, costPerKm, holeAcres, roundKm})` → `{bands: [Feature|null], gridKmUsed}`: `turf.pointGrid` (its ordering is what `turf.isobands` expects), each grid point = cheapest sample within `offStreetKm` + straight-line walk × `costPerKm` (hashed 3×3 lookup, no turf in the loop; beyond reach = unreachable, so disjoint clusters stay disjoint), one `turf.isobands` pass with every budget as a break (one annulus per interval; each band is the running `turf.union` of the annuli up to it, cheaper than a full pass per budget), drop parts < 0.5 acre, `turf.rewind` (isobands winds rings backwards), then `refine` with `roundKm` = the off-street reach (330 ft default — this rounding is what removes the per-street-end scallops; extra Chaikin passes do not), then each band is clipped to the next larger one so they stay nested. The grid grows ×1.25 until under 250,000 cells; `gridKmUsed` reports it and `computeWalkshed` returns `result.gridKmUsed`, `result.gridKmPlanned` and the tracing time as `result.shapeMs`. Unit-agnostic: walksheds use km (`costPerKm` 1), Transit Travelshed uses minutes. Shape fields `gridFt` (80, 30–500) and `offStreetFt` (330); signature `|shape:<holeAcres>:<gridFt>:<offStreetFt>`. **Cost controls:** the grid grows with the walk size, `WalkShape.scaledGridKm(gridKm, ratio)` = `gridKm × √ratio` (ratio = largest budget ÷ the 15-min budget: 1.25 km for walksheds, 15 min for Transit Travelshed), so 80 ft stays 80 ft at 15 min, ~113 ft at 30 min, 160 ft at 60 min; street samples are taken every `WalkShape.SAMPLE_STEP_CELLS` (2) grid cells, since each sample already reaches the full off-street distance. `gridKmPlanned` is the budget-scaled grid, `gridKmUsed` any further cell-cap coarsening (only the latter is reported to the user). On the test grid these changes moved band areas by under 1.5% and cut median time from ~133 to ~110 ms for 15/30 min and ~135 to ~63 ms for 45 min; the 330 ft rounding cleanup (`refine`) was then most of what remained. **Refine cost controls:** when `roundKm` ≥ ~300 ft (`COARSE_ROUND_KM`, i.e. the default 330 ft off-street reach), the outline is first simplified to a tenth of the radius and both buffers draw arcs with `steps: 4`; `turf.buffer`'s cost tracks vertex count, so this took refine from ~87 ms to ~7 ms per band and moved band areas by under 0.5%. The post-smoothing validity check is `WalkShape.selfIntersects(feature)` (grid-bucketed edge pairs, pure arithmetic, golden-pinned in `test/cases/walk-shape.mjs`) instead of `turf.kinks`, which compares every edge pair and also raises false alarms at the shared vertex of neighbouring edges (6 of 97 test outlines). Tests: `test/browser/walkshed-shape.test.mjs`, `test/browser/walkshed-contour.test.mjs`. `WalkShape.refine` (fill holes, close with a ± `roundKm` buffer, simplify ~3 m, densify, Chaikin-smooth, validity check with fallback, fill holes again; every step falls back to the previous result) is used only by contour tracing; densifying before Chaikin matters because un-densified long edges lost ~16% of a rectangle's area. The shape lives in `App.networkSettings.walkShape` `{holeAcres, gridFt, offStreetFt}` (defaults 10 acres / 80 ft / 330 ft; restore keeps only those three fields, so older sessions' `method`/`roundFt` are dropped). Helpers in `network-connectors.js`: `App.walkShapeDefaults()`, `App.walkShapeFor()` (engine object `{holeAcres, roundKm, gridKm, offStreetKm}`, ft→km; `roundKm` = the off-street reach), `App.walkShapeSignature()` (cache-key suffix), `App.setWalkShape(patch)` (saves, then notifies `App.onWalkShapeChange(fn)` listeners so BOTH modules go stale), and the shared panel wiring `App.syncWalkShapeInputs(pfx)` / `App.wireWalkShapeInputs(pfx)` (ids `<pfx>HoleAcres`, `<pfx>GridFt`, `<pfx>OffStreetFt`).

**`computeWalkshed(lngLat, budgetKm, options)`** → `{ polygon, reachableSegments (FeatureCollection), reachableCount, snap, computeMs, snapMs, floodMs } | null` (null when no network or origin snaps > `SNAP_MAX_KM`). Budget-limited flood Dijkstra, then the contour tracing above. Optional `options.budgetsKm` (ascending): floods once at the max and thresholds the same `distMap`, adding `polygons: [{budgetKm, polygon, nodeCount}]` (one per budget; sparse band → `polygon: null`, never dropped); top-level fields stay the LARGEST budget's. `window.Travelshed.bandNodeSets` was rejected for this — converting the large `Map` to a plain object costs more than the inline loop. `options.crossingPenaltyKm` → see below.

**Transit Travelshed primitives.** `computeWalkCostMap(lngLat, budgetKm)` → `{ distMap: Map<nodeKey, distKm>, snap, accessNodes: [{nodeKey, extraKm}×2], computeMs, snapMs, floodMs } | null` — raw cost map plus the two straight-line access bridges to the bracketing segment endpoints. `nodeKeyToCoord(key)`; `snapWalk(lngLat)` = `snapToNetwork(lngLat, "walk")`. **Atomicity rule:** `computeWalkCostMap`/`computeWalkshed` are synchronous; temp snap-node injection + flood + cleanup (`finally`) happen in one call. Callers may yield between calls, never during.

**`getWalkNetworkSegments()`** → plain array of `{ coords: [[lng,lat],[lng,lat]], kind: "base"|"connector", sidewalk, footway, hwy, wayId, excluded, name }` for segments where `pedBlocked` is false OR `userExcluded` is true (excluded streets must stay visible/clickable). Strings default `""`, `wayId` `null` on connector segments / legacy imports. Cached by epoch (same array reference while unchanged).

**Connector overlay.** `App.setNetworkConnectors(connectors: [{id, coords}], {snapToleranceKm})` — called only by `network-connectors.js`; stores them and runs `rebuildNetwork()`. `applyConnectorOverlay()` gathers candidates from `_segGrid` (expanded by 1 cell), calls `window.ConnectorGraph.planarizeConnectors(...)` with `splitCrossings: true`, removes replaced base edges, adds returned edges as `pedBlocked: false, carBlocked: true` (walk-only, never affects driving), then rebuilds `_segGrid` and `_nodeTier` (a split can create a real intersection). Report: `{ reason: "no-base-network" }` or `{ addEdges, removeSegIds, joins, orphans }` (`joins[].kind` `"crossing"`|`"weld"`); returned by `setNetworkConnectors` and readable via `App.getLastConnectorOverlayReport()` (used to re-sync after a base reload that bypassed `setNetworkConnectors`).

**Crossing penalties (off by default).** Edges/segments carry `hwy` (`""` for connectors = minor). `buildNodeTierMap(graph)` builds `_nodeTier: Map<nodeKey, "major"|"minor">` via `window.WalkCost.nodeTier()` (adjacency length = incident segments; no-penalty nodes omitted); rebuilt in `buildGraph()` and after `applyConnectorOverlay()`, cleared in `unloadRoadNetwork()`. `floodDijkstra(startKey, budgetKm, penaltyKm)` adds the tier penalty on arrival at a tagged node before the budget prune. Threaded via `runWalkFlood(..., {crossingPenaltyKm})` and `computeWalkshed` `options.crossingPenaltyKm`. `computeWalkCostMap` deliberately never passes one (Transit Travelshed out of scope — documented follow-up). Zero/absent penalties must stay byte-identical.

**Offline persistence.** Each successful download/import calls private `persistNetwork(id, source, label)`, deferred one `setTimeout(0)` (serializing blocks for hundreds of ms). Overpass ids = `extentCacheId(extentPolygon)` (bbox rounded to 3 decimals, so re-downloads replace); imports = `"file:"+name`. `App.restoreCachedNetwork()` → `Promise<boolean>`, called once at startup from `app.js` after `App.cache.restore()` (so connectors/exclusions are registered first); no-op if a network is loaded. **Must** go through the same `rebuildNetwork()` → `updateUI()` path as a live download so the epoch bumps exactly once and no restored network silently validates stale cached geometry. Restores the download extent too. Older than 48 h adds "Re-download to refresh." to the status. Startup restore keeps that newest-entry behavior.

**Unload vs. delete.** `App.unloadRoadNetwork()` drops the in-memory graph, segments, layers and download extent and bumps the epoch, but leaves IndexedDB alone; excluded streets and connectors are settings, so they persist and re-apply on the next load. Callers: Layers panel "Walk network" Remove, Add Data × and toolbar Clear. `App.clearRoadNetwork()` = delete the stored copies, then unload; callers: the Layers panel's confirmed "Delete downloaded streets" and Reset Session (so a deleted network does not resurrect on refresh). Neither is confirm-gated by itself; only the "Delete downloaded streets" menu item and the Reset Session button confirm.

**Area-matched restore.** `App.restoreNetworkCovering(extentPolygon)` → `Promise<boolean>` loads `networkStore.findCovering(extent)` through the same private `loadStoredRecord()` as startup restore (epoch bump, extent restored), replacing any live network. Walkshed (`runWalkshed`) and Transit Travelshed (`runTravelshed`) call it when no network is loaded or the loaded one doesn't cover the required extent, before showing the download button, and re-run once on success (an `afterRestore` flag stops a loop). `App.fetchRoadNetworkForExtent` also tries it before Overpass. Test: `test/browser/network-cache.test.mjs` (fails if the run after unload hits Overpass).

**Reset Session (`App.cache.reset`)** first restores `App.networkSettings` crossing seconds and snap tolerance to their defaults and calls `App.setExcludedWays([])`, before wiping localStorage (that call saves the session).

## FLM walk tiles: walk-tiles.js (`window.WalkTiles`) and walk-tiles-source.js (`App.walkTilesSource`)

A third street source beside the Overpass download and the GeoJSON file import. The First-Last Mile (FLM) walkshed project prepares a filtered pedestrian network offline and publishes it as a folder of small JSON tiles ("walk tiles", contract `contracts/walk-tiles/v0/` in the `flm_walkshed_index` repository). When a tile source is set, a walkshed that needs streets reads the few tiles covering its area instead of calling OpenStreetMap. Snapping, routing, contour shape, Census summaries and export are the same code as for any other network.

**Format in one paragraph.** A release folder holds `manifest.json` and `network/<col>_<row>.json`. Cells are 0.01 degrees; `col = floor((lon + 180) / 0.01)`, `row = floor((lat + 90) / 0.01)`. A segment is stored whole in every cell it touches, so neighbouring tiles repeat it: segments are deduplicated by `id` and copies must agree in every field.

**`window.WalkTiles` (pure; loads in the golden sandbox).**

| Function | Returns |
|---|---|
| `cellOf(lon, lat)` | `{ col, row }`, clamped to the grid; `null` for non-numbers |
| `cellsForBbox([w, s, e, n])` | every cell the box touches, by col then row; cells are closed, so an exact west or south edge also takes the neighbour; `[]` for bad input |
| `bboxOfCells(cells)` | `[w, s, e, n]` covering the cells exactly; `null` for an empty list |
| `cellsForBboxes(bboxes)` | the union of `cellsForBbox` over several boxes, each cell once, by col then row |
| `cellRectsForBboxes(bboxes)` | one rectangle of whole cells per box, duplicates removed (the map outline is their union) |
| `cellKeys(cells)` | `["col_row", …]`, the keys stored with a tile load |
| `validateManifest(obj)` | `{ ok: true, manifest }` or `{ ok: false, error: "<field>: <reason>" }`; checks only the fields the tool reads and accepts unknown extra fields |
| `tilesForCells(manifest, cells)` | manifest tile entries for those cells, in manifest order |
| `mergeTiles(tileObjects)` | `{ ok: true, segments, copies }` or `{ ok: false, error }`; validates all eleven segment fields; differing copies of one id are an error; one bad record stops the merge |
| `toRoadGeoJSON(segments)` | the LineString FeatureCollection `buildGraph` accepts |

`toRoadGeoJSON` always sets `foot: "yes"` (the FLM rules already decided walkability; `isPedForbidden` would otherwise block a `trunk` segment FLM accepted) and makes `wayId` a number when the id is a safe integer (street exclusion compares numeric ids). It also carries `flmId`, `lenFt` and `dir`, which the graph does not use.

**`App.walkTilesSource`.** Knows where the release folder is and reads files from it; knows nothing about graphs.

- `useUrl(url)` and `useFolder({ handle } | { files })` resolve `{ ok }` or `{ ok: false, error }` and never throw. A failed attempt leaves the current source working.
- `readTile(path)` rejects with the complete user text `FLM tile <path> could not be read: <reason>`. Reads of one path in flight share one promise; up to 64 parsed tiles are cached.
- `isActive()`, `manifest()`, `releaseId()`, `describe()`, `clear()`, `restore()`, `renderInfo()`.
- **The setting is per browser, never in the session file.** A session file is shared with other people and a folder on one person's disk means nothing to them. An address is remembered in `localStorage` key `mat-walk-tiles-source`; a picked folder is not remembered (re-pick each session), and picking one removes a remembered address.
- The folder picker uses `window.showDirectoryPicker` where it exists (Chrome, Edge) and the hidden `webkitdirectory` input elsewhere. Picking the parent of exactly one release folder works; a parent of several fails with "Pick the release folder itself, not its parent."
- Every real source change fires a `walk-tiles-source-changed` event on `document`. Walkshed and Transit Travelshed relabel their button from it. It is deliberately not `App.notifyProject()`, which would mark results stale although the loaded streets did not change.
- Tile data is not cleared for redistribution, so it is never committed to this repository. Same-origin is the simplest address: put the release under the app folder (Git-ignored) and serve both with one local server. A separate data server must send CORS headers.

**In road-network.js.**

- `App.fetchRoadNetworkForExtent(extent, pieces)`: with an active source it calls `loadNetworkFromTiles` (exported as `App.loadRoadNetworkFromTiles`) and never tries the store or Overpass. `pieces` is optional: an array of `[w, s, e, n]` boxes, one per selected point. Walkshed passes it, so two points at opposite ends of a city read only the tiles around each point and not every tile between them. Without `pieces` (Transit Travelshed, any Overpass download) the one rectangle of `extent` is used. The toolbar's "Area Roads for Street Routing" is unchanged and still downloads from OpenStreetMap.
- `loadNetworkFromTiles` uses the same tail as a download (`_roadGeoJSON`, `rebuildNetwork()`, extent, `updateUI(true)`, `persistNetwork`). It records the **cells asked for** in `_tileCells` (not the tiles found: a cell with no tile has no exported streets and still counts as covered). A new load replaces the previous network; tiles already read come from the source's in-memory cache.
- **Coverage of a tile network is answered by cells, never by polygon.** `App.roadNetworkCoversExtent(extent, pieces)` is what both panels call: for a tile network every needed cell must be in `_tileCells`; for any other network it is the old `turf.booleanContains` on the rectangle. `App.getRoadDownloadExtent()` for a tile network is the union of the per-point cell rectangles, possibly a MultiPolygon (which `turf.booleanContains` cannot test), and is for the map outline only.
- Because requested cells count as covered, `App.walkTilesExtentBeyondPrepared(extent, pieces)` exists: true when the live tile network's release is the active one and the extent (or any piece) reaches past the manifest's `coverage.bbox`. The panels use it for a soft "may be clipped" warning. The manifest itself says its box is not a guarantee of complete streets.
- Walkshed's Calculate calls this itself when a source is set and the loaded streets do not cover the run; Transit Travelshed keeps its "Load FLM tiles for this area" button because its areas can be much larger. A failed attempt to set a source stays visible in the dialog.
- Any failure (no tile for the extent, one unreadable tile, conflicting copies, source changed mid-load) leaves the live network untouched, sets the status and is kept in `App.walkTilesLastError()`. An unreadable listed tile is a failure, never an empty cell.
- `App.roadNetworkTileRelease()` is the release id when the live network was built from tiles, else `""`. An active source does not prove the live network is from tiles (a stored download may be loaded), so status text uses this, not `isActive()`.
- Stored records: id `tiles:<release_id>`, `source: "walk-tiles"`, `label: <release_id>`, `tileCells: ["col_row", …]`. One slot per release, so tile loads do not push out stored downloads. The id is deliberately not a `bbox:` id: `findCovering` matches those by rectangle, and a load of separate pieces must never claim the gap between them, so tile records are restored only at startup (with their cells) and never by area. `restoreNetworkCovering` also refuses any record that is not the active release while a source is active, so a stored download never silently replaces the FLM source. Records saved before per-point loading (`bbox:` id, no `tileCells`) are true rectangles and use the rectangle test.

**Accepted differences from the tile contract** (deliberate; do not "fix"):

| Contract | Tool |
|---|---|
| Join segments only where `from`/`to` node ids match | Joins wherever coordinates match to six decimals |
| Use `len_ft` for cost | Recomputes length with `turf.distance` |
| `dir` restricts direction | Walking is undirected (Denver has no one-way segments) |
| Snap limit 500 ft | 500 m, with the panel's 50 ft default |
| Default speed 2.8 mph | Panel default stays 3.1 mph; the dialog shows 2.8 and the user sets speed per run |

**Tests.** Golden `test/cases/walk-tiles.mjs` (fixture release in `test/fixtures/walk-tiles/fixture-release/`); behaviour `test/browser/walk-tiles.test.mjs`. The directory-handle picker cannot run headless and is checked by hand. Design record and progress log: `docs/flm-walk-tiles-plan.md` (moves to `docs/archive/` once the manual check with real Denver tiles is done).

## network-connectors.js
App-level connector orchestration (see `docs/archive/network-connectors-plan.md`).
- `App.refreshWalkNetworkLayer()` — rebuilds the "Walk network" reference layer (source `walk-network`, layer `walk-network-line`, `#94a3b8` w1 op0.45, inserted below drawn features via `firstUserLayer()`) from `App.getWalkNetworkSegments()`; removes it when no network. Called from `updateUI()` and after every overlay rebuild. At the top of every call it re-syncs its report from `App.getLastConnectorOverlayReport()` (a base reload bypasses `setNetworkConnectors`; otherwise markers go stale), and at the end calls `refreshJoinMarkers()`.
- `App.networkSettings` = `{ snapToleranceFt: 50, crossingMajorSec: 0, crossingMinorSec: 0, excludedWayIds: [] }` — global, shared by Walkshed and Transit Travelshed (never per-module); missing fields backfilled. Persisted as additive cache fields `networkSnapToleranceFt`/`networkCrossingMajorSec`/`networkCrossingMinorSec`/`networkExcludedWayIds`. `excludedWayIds` is written only through `App.setExcludedWays`.
- `App.refreshNetworkConnectors()` — `collectConnectorLines()` scans `App.lines` for `attributes.networkRole === "connector"` (skipping hidden) into `{id: "line:"+idx, coords}` (the only App.lines → plain geometry translation); no-ops on an unchanged `JSON.stringify` signature (geometry + tolerance), else calls `App.setNetworkConnectors(connectors, {snapToleranceKm: ft * 0.0003048})`, caches the report, refreshes the layer. The signature guard makes it safe to call without debouncing from `App.notifyProject()`, line vertex drag-end (`editing.js`), the `networkRole` `onChange` (`feature-attributes.js`), and both modules' snap-tolerance inputs.
- `App.getConnectorReport()` — last cached report.
- `App.getConnectorReportSummary()` → `{ text, detail, warn } | null` (null when no connectors) — "N walk connectors · M joins · K ends not connected"; on `warn`, `detail` names the worst orphan by Line name and nearest-street distance (ft).
- Join markers: source `network-joins` / layer `network-joins-point`, one data-driven `["match", ["get","kind"], ...]` circle paint — small dots for crossing/weld, larger hollow amber circles for orphans.

**Manual street exclusion.** Excluded segments are drawn by a second layer **`walk-network-excluded-line`** (`WN_EXCLUDED_LAYER`, same source, `filter: ["==", ["get","excluded"], true]`, red/dashed). **Never put a data expression in `line-dasharray`** — MapLibre only accepts a static array/zoom function there; a `["case", ...]` makes `map.addLayer` silently refuse the layer (this once took down the whole walk network). Hover layer **`walk-network-hover-line`** (`WN_HOVER_LAYER`) filters on `wayId` to highlight a whole way. `wireWalkNetworkInteraction(map)` runs exactly once per page (guarded by private `_wnWired` — delegated layer listeners survive both `setData()` AND `removeLayer()`, so a clear + re-download would otherwise stack a second click handler whose double toggle is a silent no-op; `test/browser/street-exclusion.test.mjs`). **Exclusion is opt-in:** hover and click do nothing unless the private `_exclusionMode` is on and no draw tool is active (`App.drawMode` null). `App.setWayExclusionMode(bool)` / `App.isWayExclusionMode()` own it; it is not persisted, turns off when the network is cleared, when a toolbar draw tool is picked (`app.js`) and when the Walkshed panel closes, and fires a `wayexclusionmodechange` document event (the Walkshed "Edit streets" button follows it). Hover popup (name, default "Unnamed street"; length ft; Walkable/Excluded), click → `toggleExcludedWay(wayId)` → `App.setExcludedWays()`. `wayId: null` segments (legacy imports) are skipped for hover and give a status message on click. Layers panel: `walk-network-line`, `walk-network-excluded-line`, `network-joins-point` share the one "Walk network" row; the hover layer has none.

## walk-audit.js — `window.WalkAudit`
Pure block (golden-tested in `test/cases/walk-audit.mjs`) + App block reading `App.*` only at call time (see `docs/sidewalk-data-plan.md`).
- `WalkAudit.classifySidewalk({footway, hwy, sidewalk})` → `"footway"` (segment is itself sidewalk/footway/path/steps/pedestrian/cycleway geometry) | `"both"` (`both|yes`) | `"one-side"` (`left|right`) | `"none"` (`no|none|separate`) | `"unknown"`.
- `WalkAudit.coverageStats(segments)` → `{ roadKm, footwayKm, crossingCount, byClass: {both, oneSide, none, unknown}, pctTagged, pctBoth }`. Road = non-footway; crossings = `footway === "crossing"` or non-empty `crossing`; percentages of `roadKm`, `pctTagged` excludes `unknown`. Turf-free equirectangular lengths. Empty/null → zeros, never `NaN`.
- `App.refreshSidewalkCoverageLayer()` — source `sidewalk-coverage` / layer `sidewalk-coverage-line`, one `["match", ["get","cov"], …]` color expression (both `#16a34a`, one-side `#f59e0b`, none `#dc2626`, footway `#2563eb` heavier, unknown `#94a3b8`). Hidden by default (opt-in audit overlay). Own Layers row "Sidewalk coverage" after "Walk network" (independent toggle). Called from `updateUI()` behind a `typeof` guard; removed when no network. `App.removeSidewalkCoverageLayer()` (Layers panel Remove) removes only the layer and source and sets a private flag so routine refreshes don't re-create it; there is no separate "turn on" control, so a fresh network load (download, file, restore — `updateUI(true)` passes `{ reenable: true }`) clears the flag.
- `App.getSidewalkCoverageSummary()` → `{text, detail, warn} | null`, same pattern as `App.getConnectorReportSummary()`; `warn` when `pctTagged` < 25%. Shown in Walkshed `#wsCoverageReport` and Transit Travelshed `coverageReportHTML()`.

## connector-graph.js — `window.ConnectorGraph`
Pure planarization engine (plain `[lng,lat]` in/out; golden-tested in `test/cases/connector-graph.mjs`). Never touches the live graph, `App.lines`, or attributes; `road-network.js` supplies candidates and applies results.
- `segmentIntersection(a,b,c,d)` (local km around `a`; `null` for parallel/collinear/out of range), `pointToSegmentKm(p,a,b)` (restates `nearestOnSegmentKm`), `splitChain(coords, splits)` (`{segIndex, t, point}`, drops zero-length edges).
- `planarizeConnectors(connectors, candidates, {snapToleranceKm, weldVertices, splitCrossings})` → `{addEdges, removeSegIds, joins, orphans}`. Pass A (crossings, if `splitCrossings`) processes connectors in order against a growing pool, so later connectors can cross earlier ones (join recorded under the processing connector, `segId` = earlier connector). Pass B (welding, if `weldVertices` and tolerance > 0) runs on the final pool, order-independent.
- **Rule:** candidates are skipped when `pedBlocked && !userExcluded` — real motorways/trunks never weld/cross (bridge/freeway mitigation), user-excluded streets still can. Cases `planarize-*-userexcluded-joins` must join; `planarize-weld-pedblocked-still-rejected` / `planarize-pedblocked-exclusion` must not.
- A split/weld landing on an existing coordinate (6-decimal `nodeKey` quantum, matching road-network.js) reuses it (a `"weld"` join, no extra edge). Re-splitting an already-split piece replaces its prior `addEdges` record.

## travelshed.js — `window.Travelshed`
Pure Transit Travelshed engine (plain JSON; turf/graph work lives in `road-network.js` / `js/projects/transit-travelshed.js`). `parseHHMMtoMin`, `selectActiveBand` (wrap-aware), `initialWait`/`transferWait` (capped-initial / uncapped-transfer — `docs/archive/transit-travelshed-plan.md` App. A), `rideMinAtDistance` (runTime priority), `sampleStopPositions`, `propagateRide` (both/forward/loop-wrap), `bandNodeSets`, and `computeArrivalTimes` (origin-flood boardings, egress merge, one transfer round). Optional walk caps in minutes — `accessMaxMin`, `transferMaxMin`, `egressMaxMin` (null = uncapped; `docs/archive/transit-travelshed-v2-walk-caps-plan.md`). Also returns `alightings: [{stopKey, alightMin}]` (min per stop) for cluster-union polygonization.
