# Road network

Reference for the offline road-network stack. Read the code when this and the code disagree.

## walk-cost.js — `window.WalkCost`
Crossing-penalty classification + cost math. Pure (no turf/DOM/Map/App), same engine-namespace convention as `window.ConnectorGraph`/`window.Travelshed`/`window.TPI`; golden-tested in `test/cases/walk-cost.mjs` (see `docs/archive/walkshed-bands-and-crossing-penalties-plan.md`).
- `roadTier(hwy)` → `"major"` (primary/secondary + `_link`) or `"minor"` (everything else — `tertiary` deliberately minor, usually an unsignalized collector; unknown/absent → minor).
- `nodeTier(hwyList)` → `"major"`/`"minor"`/`null`; `null` when fewer than 3 edges meet (shape point / dead end), which keeps the penalty off most vertices.
- `penaltyKm(tier, {majorSec, minorSec, speedKmh})` → `speedKmh * sec / 3600` (constant wall-clock delay regardless of speed); 0 for null tier or zero/absent sec/speed.
- Node-uniform, not turn-aware — deliberate approximation (over-charges travel along an arterial). Motorway/trunk never reach it (already `pedBlocked`).

## network-store.js — `App.networkStore`
IndexedDB cache for the downloaded network (too large for `localStorage`, expensive to re-fetch from Overpass). DB `mat-network-cache`, store `networks`, keyed by `id`, `savedAt` index. Record: `{ id, savedAt, source: "overpass"|"file", label, featureCount, extent (Feature<Polygon>|null), geojson (JSON string) }`.
- `App.networkStore.supported()` → bool (false e.g. in some private modes; callers degrade to "no cache").
- `App.networkStore.save(record)` → `Promise<boolean>`, never rejects. Writes, then prunes oldest-first to `MAX_ENTRIES`; a failed write (quota) retries once after dropping every OTHER network, then gives up quietly.
- `App.networkStore.latest()` → `Promise<record|null>`, never rejects. Reads the `savedAt` key list first, fetches only the winner (others' geojson never deserialized).
- `App.networkStore.clear()` → `Promise<boolean>`; called by `clearRoadNetwork()`.
- `App.networkStore.MAX_ENTRIES` = 3.

Everything is an optimization: failures are swallowed and callers fall back to a fresh download.

**Rule — `_withStore(mode, fn)`:** an IndexedDB transaction deactivates when control returns to the event loop, so `await`ing one request then touching the store throws `TransactionInactiveError` when the main thread is busy (i.e. page startup, exactly when this store is read). `fn` must issue requests synchronously or from another request's `onsuccess`, never after an `await`. Do not copy the `_idbTx`/`await` shape of the Recent Projects store in `cache.js`.

## road-network.js
Overpass/file import → graph → Dijkstra. Graph weights are **km**; `budgetKm = walkSpeedKmh * minutes / 60` (Walkshed's UI is mph and converts first).

**Public API:** `App.roadNetworkLoaded()` (bool), `roadNetworkEpoch()` (int, bumped on every (re)build/clear — epoch-keyed module caches use it), `findLocalRoute(waypoints)` (driving), `fetchRoadNetwork()`, `loadRoadNetworkFromFile(file)`, `exportRoadNetwork()`, `clearRoadNetwork()`, `clearRoadDownloadArea()` (outline only, graph kept — Layers panel), `restoreCachedNetwork()`, `computeWalkshed`, `computeWalkCostMap`, `polygonizeNodeSet`, `nodeKeyToCoord`, `snapWalk`, `getRoadDownloadExtent`, `fetchRoadNetworkForExtent`, `App.getWalkNetworkSegments()`, `App.setNetworkConnectors`, `App.getLastConnectorOverlayReport`, `App.setExcludedWays`.

**Rebuild choke point.** Private `rebuildNetwork()` = `buildGraph(_roadGeoJSON)` → `applyConnectorOverlay()` → one `_networkEpoch++`. Every base load (`fetchNetworkForBounds`/`loadRoadNetworkFromFile`), connector change and exclusion change routes through it, so connectors/exclusions are never merged into `_roadGeoJSON` and re-apply automatically after a re-download. `updateUI()` is the single choke point for map-side refresh (download outline, `App.refreshWalkNetworkLayer()`, `App.refreshSidewalkCoverageLayer()`); `rebuildNetwork()` alone does NOT refresh map sources.

**Download.** `fetchRoadNetwork()` fetches the current view expanded ×1.5 per side (`turf.transformScale`), vehicle roads plus `living_street|pedestrian|footway|path|steps|cycleway`, capturing `foot`; `window.confirm` above `MAX_AREA_WARN_KM2` (2000 km²). Extent recorded as `_downloadedBboxPolygon`, drawn as a dashed `#c026d3` outline (`road-dl-area` / `road-dl-area-line`, Layers "Road download area"); file imports have no outline. `fetchRoadNetworkForExtent(extentPolygon)` → `Promise<boolean>` downloads a caller-supplied extent (same helper), replacing the network and bumping the epoch. `getRoadDownloadExtent()` → `Feature<Polygon>|null`. The parse also captures `sidewalk`, `footway`, `crossing` and `wayId` (parse-side only; `out geom;` already returns them). These go on `_segmentIndex` entries, deliberately not on graph edge objects (hot path, allocated twice per segment).

**Class-aware traversal.** `buildGraph()` tags each edge/segment `pedBlocked`/`carBlocked` via `isPedForbidden(hwy, foot)` (motorway/trunk + `_link`) / `isCarForbidden(hwy)` (footway/path/steps/pedestrian/cycleway); explicit `foot=yes/designated/permissive`/`foot=no` override. Walk flood skips `pedBlocked`, driving `dijkstra` skips `carBlocked`, `snapToNetwork(lngLat, mode)` filters per mode (`"walk"`/`"drive"`, absent = no filter). One download, two interpretations.

**User-excluded streets.** `buildGraph()` ORs the private `_excludedWays` Set into `pedBlocked` and records `userExcluded` separately, so the flood skips it but segments/`connector-graph.js` can still tell it apart; `carBlocked` untouched. **`App.setExcludedWays(ids)` is the ONLY write path**: sets the Set, writes `App.networkSettings.excludedWayIds`, `App.cache.save()`, `rebuildNetwork()`, then `updateUI()` (without `updateUI()` an exclusion changed routing but not the map — a past bug). `collectCandidateSegments()` passes `userExcluded` so connectors can still weld to excluded streets (see connector-graph.js).

**Snapping.** `snapToNetwork` queries a uniform grid `_segGrid` (≈0.5 km cells, built in `buildGraph()`, 3×3 neighborhood covers `SNAP_MAX_KM` = 0.5 km) with inline equirectangular `nearestOnSegmentKm` math — the old whole-network turf scan cost 1–3 s/call and was the real Transit Travelshed bottleneck. Cleared in `clearRoadNetwork()`.

**`computeWalkshed(lngLat, budgetKm, options)`** → `{ polygon, reachableSegments (FeatureCollection), reachableCount, snap, computeMs, snapMs, floodMs } | null` (null when no network or origin snaps > `SNAP_MAX_KM`). Budget-limited flood Dijkstra, then concave hull with auto-relax (grow `maxEdge` → `turf.convex` → small buffer for <3 nodes). Optional `options.budgetsKm` (ascending): floods once at the max and thresholds the same `distMap`, adding `polygons: [{budgetKm, polygon, nodeCount}]` (one per budget; sparse band → `polygon: null`, never dropped); top-level fields stay the LARGEST budget's. Absent `budgetsKm` must stay byte-identical (backward-compat requirement). `window.Travelshed.bandNodeSets` was rejected for this — converting the large `Map` to a plain object costs more than the inline loop. `options.crossingPenaltyKm` → see below.

**Transit Travelshed primitives.** `computeWalkCostMap(lngLat, budgetKm)` → `{ distMap: Map<nodeKey, distKm>, snap, accessNodes: [{nodeKey, extraKm}×2], computeMs, snapMs, floodMs } | null` — raw cost map plus the two straight-line access bridges to the bracketing segment endpoints. `polygonizeNodeSet(coords, maxEdgeKm)` — the same hull polygonizer. `nodeKeyToCoord(key)`; `snapWalk(lngLat)` = `snapToNetwork(lngLat, "walk")`. **Atomicity rule:** `computeWalkCostMap`/`computeWalkshed` are synchronous; temp snap-node injection + flood + cleanup (`finally`) happen in one call. Callers may yield between calls, never during.

**`getWalkNetworkSegments()`** → plain array of `{ coords: [[lng,lat],[lng,lat]], kind: "base"|"connector", sidewalk, footway, hwy, wayId, excluded, name }` for segments where `pedBlocked` is false OR `userExcluded` is true (excluded streets must stay visible/clickable). Strings default `""`, `wayId` `null` on connector segments / legacy imports. Cached by epoch (same array reference while unchanged).

**Connector overlay.** `App.setNetworkConnectors(connectors: [{id, coords}], {snapToleranceKm})` — called only by `network-connectors.js`; stores them and runs `rebuildNetwork()`. `applyConnectorOverlay()` gathers candidates from `_segGrid` (expanded by 1 cell), calls `window.ConnectorGraph.planarizeConnectors(...)` with `splitCrossings: true`, removes replaced base edges, adds returned edges as `pedBlocked: false, carBlocked: true` (walk-only, never affects driving), then rebuilds `_segGrid` and `_nodeTier` (a split can create a real intersection). Report: `{ reason: "no-base-network" }` or `{ addEdges, removeSegIds, joins, orphans }` (`joins[].kind` `"crossing"`|`"weld"`); returned by `setNetworkConnectors` and readable via `App.getLastConnectorOverlayReport()` (used to re-sync after a base reload that bypassed `setNetworkConnectors`).

**Crossing penalties (off by default).** Edges/segments carry `hwy` (`""` for connectors = minor). `buildNodeTierMap(graph)` builds `_nodeTier: Map<nodeKey, "major"|"minor">` via `window.WalkCost.nodeTier()` (adjacency length = incident segments; no-penalty nodes omitted); rebuilt in `buildGraph()` and after `applyConnectorOverlay()`, cleared in `clearRoadNetwork()`. `floodDijkstra(startKey, budgetKm, penaltyKm)` adds the tier penalty on arrival at a tagged node before the budget prune. Threaded via `runWalkFlood(..., {crossingPenaltyKm})` and `computeWalkshed` `options.crossingPenaltyKm`. `computeWalkCostMap` deliberately never passes one (Transit Travelshed out of scope — documented follow-up). Zero/absent penalties must stay byte-identical.

**Offline persistence.** Each successful download/import calls private `persistNetwork(id, source, label)`, deferred one `setTimeout(0)` (serializing blocks for hundreds of ms). Overpass ids = `extentCacheId(extentPolygon)` (bbox rounded to 3 decimals, so re-downloads replace); imports = `"file:"+name`. `App.restoreCachedNetwork()` → `Promise<boolean>`, called once at startup from `app.js` after `App.cache.restore()` (so connectors/exclusions are registered first); no-op if a network is loaded. **Must** go through the same `rebuildNetwork()` → `updateUI()` path as a live download so the epoch bumps exactly once and no restored network silently validates stale cached geometry. Restores the download extent too. Older than 48 h adds "Re-download to refresh." to the status. `clearRoadNetwork()` also empties the store — clearing is explicit and confirm-gated, so a cleared network must not resurrect on refresh.

## network-connectors.js
App-level connector orchestration (see `docs/archive/network-connectors-plan.md`).
- `App.refreshWalkNetworkLayer()` — rebuilds the "Walk network" reference layer (source `walk-network`, layer `walk-network-line`, `#94a3b8` w1 op0.45, inserted below drawn features via `firstUserLayer()`) from `App.getWalkNetworkSegments()`; removes it when no network. Called from `updateUI()` and after every overlay rebuild. At the top of every call it re-syncs its report from `App.getLastConnectorOverlayReport()` (a base reload bypasses `setNetworkConnectors`; otherwise markers go stale), and at the end calls `refreshJoinMarkers()`.
- `App.networkSettings` = `{ snapToleranceFt: 50, crossingMajorSec: 0, crossingMinorSec: 0, excludedWayIds: [] }` — global, shared by Walkshed and Transit Travelshed (never per-module); missing fields backfilled. Persisted as additive cache fields `networkSnapToleranceFt`/`networkCrossingMajorSec`/`networkCrossingMinorSec`/`networkExcludedWayIds`. `excludedWayIds` is written only through `App.setExcludedWays`.
- `App.refreshNetworkConnectors()` — `collectConnectorLines()` scans `App.lines` for `attributes.networkRole === "connector"` (skipping hidden) into `{id: "line:"+idx, coords}` (the only App.lines → plain geometry translation); no-ops on an unchanged `JSON.stringify` signature (geometry + tolerance), else calls `App.setNetworkConnectors(connectors, {snapToleranceKm: ft * 0.0003048})`, caches the report, refreshes the layer. The signature guard makes it safe to call without debouncing from `App.notifyProject()`, line vertex drag-end (`editing.js`), the `networkRole` `onChange` (`feature-attributes.js`), and both modules' snap-tolerance inputs.
- `App.getConnectorReport()` — last cached report.
- `App.getConnectorReportSummary()` → `{ text, detail, warn } | null` (null when no connectors) — "N walk connectors · M joins · K ends not connected"; on `warn`, `detail` names the worst orphan by Line name and nearest-street distance (ft).
- Join markers: source `network-joins` / layer `network-joins-point`, one data-driven `["match", ["get","kind"], ...]` circle paint — small dots for crossing/weld, larger hollow amber circles for orphans.

**Manual street exclusion.** Excluded segments are drawn by a second layer **`walk-network-excluded-line`** (`WN_EXCLUDED_LAYER`, same source, `filter: ["==", ["get","excluded"], true]`, red/dashed). **Never put a data expression in `line-dasharray`** — MapLibre only accepts a static array/zoom function there; a `["case", ...]` makes `map.addLayer` silently refuse the layer (this once took down the whole walk network). Hover layer **`walk-network-hover-line`** (`WN_HOVER_LAYER`) filters on `wayId` to highlight a whole way. `wireWalkNetworkInteraction(map)` runs exactly once after first layer creation (layer listeners survive `setData()`; re-wiring would stack handlers): hover popup (name, default "Unnamed street"; length ft; Walkable/Excluded), click → `toggleExcludedWay(wayId)` → `App.setExcludedWays()`. `wayId: null` segments (legacy imports) are skipped for hover and give a status message on click. Layers panel: `walk-network-line`, `walk-network-excluded-line`, `network-joins-point` share the one "Walk network" row; the hover layer has none.

## walk-audit.js — `window.WalkAudit`
Pure block (golden-tested in `test/cases/walk-audit.mjs`) + App block reading `App.*` only at call time (see `docs/sidewalk-data-plan.md`).
- `WalkAudit.classifySidewalk({footway, hwy, sidewalk})` → `"footway"` (segment is itself sidewalk/footway/path/steps/pedestrian/cycleway geometry) | `"both"` (`both|yes`) | `"one-side"` (`left|right`) | `"none"` (`no|none|separate`) | `"unknown"`.
- `WalkAudit.coverageStats(segments)` → `{ roadKm, footwayKm, crossingCount, byClass: {both, oneSide, none, unknown}, pctTagged, pctBoth }`. Road = non-footway; crossings = `footway === "crossing"` or non-empty `crossing`; percentages of `roadKm`, `pctTagged` excludes `unknown`. Turf-free equirectangular lengths. Empty/null → zeros, never `NaN`.
- `App.refreshSidewalkCoverageLayer()` — source `sidewalk-coverage` / layer `sidewalk-coverage-line`, one `["match", ["get","cov"], …]` color expression (both `#16a34a`, one-side `#f59e0b`, none `#dc2626`, footway `#2563eb` heavier, unknown `#94a3b8`). Hidden by default (opt-in audit overlay). Own Layers row "Sidewalk coverage" after "Walk network" (independent toggle). Called from `updateUI()` behind a `typeof` guard; removed when no network.
- `App.getSidewalkCoverageSummary()` → `{text, detail, warn} | null`, same pattern as `App.getConnectorReportSummary()`; `warn` when `pctTagged` < 25%. Shown in Walkshed `#wsCoverageReport` and Transit Travelshed `coverageReportHTML()`.

## connector-graph.js — `window.ConnectorGraph`
Pure planarization engine (plain `[lng,lat]` in/out; golden-tested in `test/cases/connector-graph.mjs`). Never touches the live graph, `App.lines`, or attributes; `road-network.js` supplies candidates and applies results.
- `segmentIntersection(a,b,c,d)` (local km around `a`; `null` for parallel/collinear/out of range), `pointToSegmentKm(p,a,b)` (restates `nearestOnSegmentKm`), `splitChain(coords, splits)` (`{segIndex, t, point}`, drops zero-length edges).
- `planarizeConnectors(connectors, candidates, {snapToleranceKm, weldVertices, splitCrossings})` → `{addEdges, removeSegIds, joins, orphans}`. Pass A (crossings, if `splitCrossings`) processes connectors in order against a growing pool, so later connectors can cross earlier ones (join recorded under the processing connector, `segId` = earlier connector). Pass B (welding, if `weldVertices` and tolerance > 0) runs on the final pool, order-independent.
- **Rule:** candidates are skipped when `pedBlocked && !userExcluded` — real motorways/trunks never weld/cross (bridge/freeway mitigation), user-excluded streets still can. Cases `planarize-*-userexcluded-joins` must join; `planarize-weld-pedblocked-still-rejected` / `planarize-pedblocked-exclusion` must not.
- A split/weld landing on an existing coordinate (6-decimal `nodeKey` quantum, matching road-network.js) reuses it (a `"weld"` join, no extra edge). Re-splitting an already-split piece replaces its prior `addEdges` record.

## travelshed.js — `window.Travelshed`
Pure Transit Travelshed engine (plain JSON; turf/graph work lives in `road-network.js` / `js/projects/transit-travelshed.js`). `parseHHMMtoMin`, `selectActiveBand` (wrap-aware), `initialWait`/`transferWait` (capped-initial / uncapped-transfer — `docs/archive/transit-travelshed-plan.md` App. A), `rideMinAtDistance` (runTime priority), `sampleStopPositions`, `propagateRide` (both/forward/loop-wrap), `bandNodeSets`, and `computeArrivalTimes` (origin-flood boardings, egress merge, one transfer round). Optional walk caps in minutes — `accessMaxMin`, `transferMaxMin`, `egressMaxMin` (null = uncapped; `docs/archive/transit-travelshed-v2-walk-caps-plan.md`). Also returns `alightings: [{stopKey, alightMin}]` (min per stop) for cluster-union polygonization.
