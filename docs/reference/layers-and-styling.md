# Layers and styling

Reference detail moved verbatim from `CLAUDE.md`. Read the code when this and the code disagree.

## Files

- **`layer-palettes.js`** — Layer color customization (`docs/layer-color-customization-plan.md`). Two halves in one file, same split as `walk-cost.js`/`travelshed.js`: a pure `window.LayerPalette` block (no turf/DOM/Map/App state, golden-tested) followed by an App-level cascade block that reads/writes `App.*` at call time. **Pure half:** `PALETTES` (11 curated presets — `blues`/`greens`/`heat`/`viridis`/`plasma`/`inferno`/`magma`/`cividis`/`gray` sequential, `rdbu`/`quality` diverging — each `{label, family, colors5}` running light→dark or low-end→high-end; `viridis`/`plasma`/`inferno`/`magma`/`cividis` are matplotlib's perceptually-uniform family, added for higher-contrast alternatives to the ColorBrewer-style presets, with `cividis` additionally chosen for being colorblind-safe (deuteranopia/protanopia) — none of the other ten presets are), `LAYER_STYLES` (one spec per styleKey — `walkshed`, `walkshed-seg`, `transit-travelshed`, `tpi`, `rf`, `corridor-scoring`, `gtfs-shapes`, `gtfs-stops` — each `{label, kind: "ramp"|"solid", n?, prop?, allow?, reverseDefault?, defaultColors}`, `defaultColors` verified byte-identical to what each module already painted so the whole plan through Phase 5 is a provable no-op), `list(allow)`, `rampColors(paletteId, n, reverse)` (same subsampling arithmetic as `choropleth.js`'s `pickRampColors`, with one intentional divergence: a subsampled color (`n < 5`) whose average channel exceeds `LIGHTNESS_CEILING` (180 — a first pass at 225 still read too faint against a light basemap, though it was fine on a dark one) is scaled down toward that ceiling, hue/saturation preserved — a post-ship fix for Blues/Greens/Grayscale's near-white `colors5[0]` reading as invisible on Walkshed/Transit Travelshed's `n: 3` outermost band over a light basemap; `n >= colors5.length` (TPI/RF's `n: 5`) bypasses the clamp entirely so no existing default changed, and `gradientColors()`'s user-picked endpoints are deliberately exempt — see `docs/layer-color-customization-plan.md`'s "Post-ship fix" section), `gradientColors(from, to, n)` + `rgba(hex, alpha)` (Phase 7 — see the App half below), `matchExpr(prop, colors)` (builds a MapLibre `match` expression, the same shape `walkshed.js`/`transit-travelshed.js` already used inline), `familyOf(paletteId)`, `allows(spec, paletteId)` (the single function enforcing that a palette only reaches a layer whose `allow` list accepts its family — this is what keeps Corridor Scoring's diverging-only restriction meaningful rather than cosmetic), `specFor(styleKey)`. A third spec kind, `kind: "categorical"` (Phase 7 — `transit-coverage`, `title-vi`), carries a `classes: [{key, label}]` array positional against `defaultColors`: independent semantic colors (coverage/threshold/service-area; service loss/gain), one swatch per class rather than a ramp. **App half:** `App.layerStyles` (per-styleKey override map, `{palette, reverse, color}`, persisted), `App.mapPalette` (one global palette id or null, persisted), `App.resolveLayerColors(styleKey)` (the three-level cascade — per-layer override → global palette, only if `allows()` accepts it → `spec.defaultColors` — returning an array of hex strings or `null` for an unknown styleKey; solid-kind layers ignore `App.mapPalette` entirely), `App.setLayerStyle(styleKey, patch)`/`App.clearLayerStyle(styleKey)` (shallow-merge or delete, save to cache, `App.repaintStyledLayers()` — the only sanctioned write path; nothing outside this file calls `map.setPaintProperty` for a styled layer), `App.registerLayerRepainter(styleKey, fn)`/`App.repaintStyledLayers(only)` (a registry of cheap paint-only refresh callbacks, one per consuming module, each wrapped in its own try/catch so a module with no live layer on the map is a no-op, not a thrown error that blocks the others). Consumed by `choropleth.js` (`render()`'s optional `opts.colors`), `walkshed.js`, `transit-travelshed.js`, `transit-propensity.js`, `ridership-forecasting.js`, `corridor-scoring.js`, `gtfs.js` (Phase 4), the four static legend fragments (Phase 5), and `layers-panel.js`'s per-layer style drawers + global palette row (Phase 6).

- **`layers-panel.js`** — "Layers" tab on the right feature panel (sibling of the "Features" tab). Unified map-layer manager: a Drawn band (features nested by `attributes.group` with per-group/-feature visibility + color), Analysis overlays and Reference/Imported bands (only layers currently on the map) with per-layer show/hide + opacity + constrained drag-reorder + a ⋯ menu (zoom to, open module, remove), and a Basemap selector. Declarative layer manifest (REFERENCE/ANALYSIS) keyed by MapLibre layer id; renders only present layers. The `ANALYSIS` manifest's first entry is `bas-choropleth-fill`/`bas-choropleth-line` (label "Feature Area Analysis", `moduleId: "buffer-summary"`) — added alongside the Feature Area Analysis choropleth (`docs/feature-area-choropleth-plan.md` Phase 1) following the same one-entry-per-module pattern as the TPI/Corridor Scoring/RF/etc. entries beneath it. The Walkshed entry in `ANALYSIS` is split into two rows — `walkshed-fill` (fill + outline) and `walkshed-seg` (label "Walkshed — reachable streets", the green correctness layer) — so the reachable-streets overlay can be hidden independently of the walkshed polygon; each still only renders when its layer is actually on the map (`docs/walkshed-bands-and-crossing-penalties-plan.md` Phase 1). The `REFERENCE` manifest's "Walk network" entry (`walk-network-line`) carries a second sub-layer, `network-joins-point` (`docs/network-connectors-plan.md` Phase 6 — the join/orphan marker circles), in the same `layers` array rather than as a separate row, matching the multi-layer-per-row pattern the choropleth entries already use (opacity toggles both together). Directly after it sits "Sidewalk coverage" (`sidewalk-coverage-line`, `docs/sidewalk-data-plan.md` Phase 2) as its **own row**, not folded into the walk-network row's `layers` array — different semantics (the sidewalk attribute on road centerlines vs. the walkable segments the flood uses) and independently toggled, hidden by default. A layer row with no style drawer gets an invisible `.lp-caret-spacer` (same 24px width as the caret) so every row's drag handle and name share one left edge. Reorder is clamped within a band via map.moveLayer (drawn features stay on top; drawn groups can't z-reorder since a geometry type shares one layer). Two-way visibility sync with the Add Data eye/× icons. Toggling a styled entry's eye icon also calls `App.repaintStyledLayers(entry.styleKey)` when the entry carries a `styleKey`, so a module can react to its own layer's visibility changing (not just its color) — e.g. Walkshed hides its legend's "Reachable streets" row when the `walkshed-seg` layer is hidden; a module with nothing to do here simply doesn't register extra behavior in its repainter, so this is a no-op for every other styled layer. **Style defaults:** below the grouped feature list, a "Style defaults" heading introduces one collapsible style-drawer row per drawn geometry type that currently has features (Points/Lines/Routes/Polygons/Buffers, `DRAWN_TYPES`), each with a small live SVG preview and controls (a color swatch plus `App.buildScrubber` numeric controls for opacity/weight, driven by `App.featureSettings` and, for color, `App.sectionColors`) and a Reset button. The color swatch is a live default resolved via `App.resolveFeatureColor` (`docs/feature-color-system-plan.md`), not a "next feature will be stamped with this" picker: changing it retroactively recolors every feature of that type which doesn't carry its own override, not just future ones. When `sectionColors[type]` is `null` (Automatic) the Lines/Routes swatch renders as a small multi-stop gradient sampled from `App.FEATURE_COLORS` (each feature still varies via its own `colorSeq`) rather than a flat color — Points/Polygons have no rainbow mode, so Automatic there just shows the built-in default. Once a flat color is set, a small `.lp-style-clear` button appears next to the swatch to reset the type back to Automatic (`resetTypeStyle` already did this; the button just exposes it). **Per-feature overrides:** each feature row in the grouped list also gets a caret opening a per-feature override drawer whose rows are built by `App.buildFeatureOverrideRows` (`js/core/feature-appearance.js` — the same builder the Appearance popover uses; opacity, width, offset for lines/routes, opacity/width/offset only — the Phase 2 Buffer row was removed (buffer radius is edited via `App.buildBufferRadiusControl`, `docs/feature-appearance-plan.md`; every edit takes one undo snapshot per gesture) — each control shows the type default in muted text until the feature has its own override (`feature.properties._opacity`/`_fillOpacity`/`_borderOpacity`/`_lineWidth`/`_bufferRadius`/`_offset`), and gains a small clear button once it does. The feature row's own type-icon swatch (in the grouped list, not the drawer) now opens the shared Appearance popover on click (`App.openAppearancePopup`), and still follows the same pattern: it shows the resolved color always, and gains a `.lp-style-clear` button once `properties.color` is non-empty, resetting it back to `""` (inherit). Together with the Appearance popover this is the appearance cascade's UI — see the `App.featureSettings` entry below for the full field list. **GTFS route browser (Phase 2 of `docs/gtfs-route-browser-plan.md`):** the "GTFS routes" reference row gets an expand caret (`decorateGtfsRow`); expanded, it shows a filter box (`.lp-gtfs-filter`, via `App.gtfsBrowse.filterRoutes`), Show all / Hide all / Show only filtered, and one two-line row per route (color dot, short name, `(n shapes)` + muted long name, always-visible eye + ⋯; max 200 rows, then "Showing 200 of N — refine the filter"). Shape rows are built lazily on first expand (shape_id; length mi · trips · top headsign). Hover/focus calls `App.gtfsHighlight`; click pins the highlight (double-click pins + zooms); the eye calls `gtfsSetRouteHidden`/`gtfsSetShapeHidden` (a shape under a hidden route is dimmed and its eye shows the route); ⋯ / right-click / ContextMenu / Shift+F10 open `App.showContextMenu` menus (route: Copy as line, Copy each shape as a line, Copy all as grouped Service, Show only this, Zoom to; shape: Copy as line, Show only this route, Zoom to). Copies are followed by `App.selectFeature("line", firstNewIndex)`. UI state (`_gtfsUI`: open, filter, expanded routes, pinned target) lives in the module so it survives `render()`; `render()` also preserves `.fp-content` scroll and filter focus/caret, and typing in the filter re-renders only the list. Nothing is drawn when `App.gtfsRouteIndex()` is null; a new feed resets the UI state. Styles: `.lp-gtfs-*` in `css/style.css`. Reuses properties.hidden, App.rerenderForType, App.openColorPicker, App._openFpSlider, App.buildScrubber, App.applyFeatureOpacity, App.applyLineWidth, App.applyBufferLineWidth, App._polyOpacityValues, App.showContextMenu, basemap API. **Analysis/reference layer color styling (`docs/layer-color-customization-plan.md` Phase 6):** the `ANALYSIS`/`REFERENCE` manifest entries that have one carry a `styleKey` (`walkshed-fill`→`walkshed`, `walkshed-seg`→`walkshed-seg`, `ts-travelshed-fill`→`transit-travelshed`, `tpi-choropleth-fill`→`tpi`, `rf-choropleth-fill`→`rf`, `corridor-scoring-routes-layer`→`corridor-scoring`, `gtfs-shapes-layer`→`gtfs-shapes`, `gtfs-stops-layer`→`gtfs-stops`, and as of Phase 7 `transit-coverage-coverage-layer`→`transit-coverage` and `tvi-impacted-fill`→`title-vi`; Feature Area Analysis, walk network, OSM, census geos, muni boundaries, road-download-area and FTA sites deliberately carry none — see the plan's §1.4 and §2). `buildLayerRow()` wraps a styled entry's row in the same `.lp-style-group`/caret/`.lp-style-drawer` shape `buildTypeStyleRow()` uses for the Style-defaults rows (caret first in the row, before the grip); `buildLayerStyleDrawer()` renders, for `kind: "ramp"`, a Palette select (`Default` + `LayerPalette.list(spec.allow)` + `Custom` — four options total for Corridor Scoring, since it only accepts `diverging`) and a Reverse checkbox (seeded from the override or `spec.reverseDefault`, disabled while the select reads Default), plus — only when `spec.flattenOption` is set (today just `"walkshed"`) — a "Flatten overlaps" checkbox writing `App.setLayerStyle(styleKey, {flatten})`, orthogonal to color so it renders in both the Custom-gradient and preset-palette branches; the Reset button (shown when any of palette/reverse/flatten is overridden) still clears the whole entry via `App.clearLayerStyle`; for `kind: "solid"`, a `.lp-swatch` opening `App.openColorPicker` plus a `.lp-style-clear` × shown only once a color override exists (no separate Reset — the × already is one, per the plan's §6.2); for `kind: "categorical"` (Phase 7), one `label + swatch + ×` row per `spec.classes` entry and no palette select (three rows for Transit Coverage, two for Title VI), writing through `App.setLayerClassColor`. Selecting **Custom** on a ramp layer swaps the Reverse row for a **Colors** row carrying the gradient's two endpoint swatches — reversing a 2-stop gradient is just swapping those two picks, so this keeps the drawer at the §3 three-row ceiling — and seeds `from`/`to` from the layer's currently-resolved first and last colors, making the switch a visual no-op. `buildSwatchRow()` is the shared builder behind the solid drawer, the categorical rows, and the gradient endpoints. Every control writes through `App.setLayerStyle`/`App.clearLayerStyle` and re-renders the panel — **never `map.setPaintProperty` directly**, matching the invariant the whole plan exists to enforce (see the `layer-palettes.js` entry above). One global palette row (`buildGlobalPaletteRow()`, `.lp-style-row` only, no caret/drawer) sits at the top of the Analysis overlays band, offering `Default` + all eleven palettes (`LayerPalette.list(null)`); selecting one sets `App.mapPalette`, saves, and calls `App.repaintStyledLayers()`. Both drawer and global select reuse the `.lp-basemap-select` class (capped to 104px inside `.lp-style-control` via one added CSS rule, per the plan's §6.4) rather than introducing new control styling. Reuses properties.hidden, App.rerenderForType, App.openColorPicker, App._openFpSlider, App.buildScrubber, App.applyFeatureOpacity, App.applyLineWidth, App.applyBufferLineWidth, App._polyOpacityValues, App.showContextMenu, basemap API, and (for the styling additions) `window.LayerPalette`, `App.resolveLayerColors`, `App.setLayerStyle`, `App.clearLayerStyle`, `App.layerStyles`, `App.mapPalette`, `App.repaintStyledLayers`. Exports App.refreshLayersPanel. No own persistence (drawn visibility/color/opacity already ride the session cache — including `App.sectionColors` itself, saved/restored by `cache.js`; reference/analysis order + visibility are per-session; `App.layerStyles`/`App.mapPalette` are persisted by `cache.js` itself, not by this file).

## API

### API — layer-palettes.js
Layer color customization (`docs/layer-color-customization-plan.md`) — lets a user restyle Walkshed, Transit Travelshed, TPI, Ridership Forecast (choropleth + corridor CDI lines), Corridor Scoring (diverging palettes only), and GTFS routes/stops from the Layers panel, with the choice surviving a re-run and a page reload.

**`window.LayerPalette`** (pure, golden-tested, no `App`/turf/DOM/Map at load time): `PALETTES` — 11 presets, `blues`/`greens`/`heat`/`viridis`/`plasma`/`inferno`/`magma`/`cividis`/`gray` (`family: "sequential"`) and `rdbu`/`quality` (`family: "diverging"`), each `{label, family, colors5}` running light→dark (sequential) or low-end→high-end (diverging). `list(allow)` → `[{id, label, family}]` filtered to the given family array (null/absent = all eleven, in table order). `rampColors(paletteId, n, reverse)` → `n` colors evenly subsampled from `colors5` (identical arithmetic to `choropleth.js`'s `pickRampColors`, plus a light-end visibility floor when `n < 5` — see the File Structure entry above), reversed when `reverse` is truthy; unknown id → `null`. `matchExpr(prop, colors)` → a MapLibre `["match", ["get", prop], 0, colors[0], ...]` expression, trailing color as fallback. `familyOf(paletteId)` → `"sequential"`/`"diverging"`/`null`. `allows(spec, paletteId)` → true when `spec.allow` is absent/empty or includes that palette's family — the single function enforcing that the global palette only reaches a layer whose spec accepts it (e.g. a sequential global palette never reaches Corridor Scoring). `LAYER_STYLES` — one spec per styleKey (`walkshed`, `walkshed-seg`, `transit-travelshed`, `tpi`, `rf`, `corridor-scoring`, `gtfs-shapes`, `gtfs-stops`), each `{label, kind: "ramp"|"solid", n?, prop?, allow?, reverseDefault?, defaultColors, flattenOption?}` — `defaultColors` is an explicit color array equal to exactly what that module paints with no override, not a palette id, which is what makes every phase before the Layers-panel UI a provable visual no-op. `flattenOption: true` (only `"walkshed"` sets it today) opts a ramp-kind layer into an extra "Flatten overlaps" checkbox row in `layers-panel.js`'s `buildLayerStyleDrawer` — a generic drawer flag, not walkshed-specific code, for any ramp layer whose fill can overlap across features; see `js/projects/walkshed.js`'s entry below for what it actually renders. `specFor(styleKey)` → the spec or `null`.

**App-level cascade** (reads/writes `App.*` only at call time, same rule `choropleth.js` follows): `App.layerStyles` (`{styleKey: {palette, reverse, color, from, to, colors}}`, per-layer overrides, persisted by `cache.js`), `App.mapPalette` (one global palette id or `null`, persisted). `App.resolveLayerColors(styleKey)` → an array of hex strings, or `null` for an unknown styleKey. Resolution order: (1) `App.layerStyles[styleKey]`'s override; (2) for `kind: "ramp"`, `App.mapPalette` **only if** `LayerPalette.allows(spec, App.mapPalette)`; (3) `spec.defaultColors.slice()`. Solid **and categorical** layers ignore `App.mapPalette` entirely (a global ramp says nothing about a single accent color, nor about which color "service loss" should be) — categorical resolves each class from its own sparse positional override array, written only via `App.setLayerClassColor(styleKey, idx, color)`, which owns the pad/null/collapse bookkeeping so an all-default entry still deletes outright.

**Custom 2-stop gradient (Phase 7).** A ramp layer's `palette` may be `"custom"` (`LayerPalette.CUSTOM_ID`), resolved via `gradientColors(ov.from, ov.to, spec.n)` — a channel-wise sRGB lerp, the same thing MapLibre's own `["interpolate", ["linear"], …]` does between two stops. It is **per-layer only and never global**: `"custom"` is deliberately not a `PALETTES` member, so `list()`/`familyOf()`/`allows()` never see it and the global palette row cannot be set to it. That is the design line — a custom gradient is two deliberate picks on one layer (the colorblind and agency-branding cases, and why it is offered even on Corridor Scoring despite its `allow: ["diverging"]`: a two-color pick cannot be made by accident), while the global control stays restricted to curated families so it can never make a semantic layer unreadable in one click. The gradient is literal and WYSIWYG — `from` always paints the first class, `to` the last, ignoring both `spec.reverseDefault` and any stale `ov.reverse` left over from a preset. `rgba(hex, alpha)` exists because the static legend fragments paint a translucent fill plus a solid border from one source color, so their fill functions need both forms of a resolved color. A ramp override's `reverse` defaults to `spec.reverseDefault` when not itself overridden — Walkshed/Transit Travelshed default `true` (dark = fewest minutes); TPI/RF/Corridor Scoring default `false` (dark = high score). `App.setLayerStyle(styleKey, patch)` — shallow-merges `patch` (`palette`/`reverse`/`color`/`from`/`to`/`colors`, plus `flatten` — a plain boolean a `spec.flattenOption` layer can opt into, e.g. Walkshed's overlap-flattening display toggle; see that module's entry below), deletes the entry entirely once every field is null/absent, calls `App.cache.save()`, then `App.repaintStyledLayers()`. `App.clearLayerStyle(styleKey)` — deletes the entry, saves, repaints. `App.registerLayerRepainter(styleKey, fn)`/`App.repaintStyledLayers(only)` — a registry of cheap refresh callbacks (one per consuming module — see each module's entry below), each wrapped in its own try/catch so a module with no live layer on the map is a no-op rather than an error that blocks the others; this is what makes a palette change repaint instantly without re-running the analysis. Usually paint-only (`map.setPaintProperty`), but a module MAY re-render geometry instead when a `flattenOption` change needs it — Walkshed's repainter re-derives its fill features from its own already-computed results rather than touching product-level analysis state, so this is still cheap and still never a recompute of the underlying flood. **The Layers panel (`layers-panel.js`) is the only UI surface and never calls `map.setPaintProperty` itself** — it only ever calls `App.setLayerStyle`/`App.clearLayerStyle`; every consuming module owns its own repaint via the registry, exactly mirroring the drawn-feature appearance cascade's split between `App.sectionColors`/`App.featureSettings` (state) and each render function (application).

### API — layers-panel.js
`refreshLayersPanel()` — rebuilds the Layers tab from current map state (no-op when the tab is hidden). Called from the tab toggle, `App.notifyProject()`, and `App.updateAddDataClearIcons()`. No other public API (the manifest, drag-reorder, and ⋯ actions are private to the module).
