# Layers and styling

Read the code when this and the code disagree. Design: `docs/archive/layer-color-customization-plan.md`.

## layer-palettes.js

Two halves: a pure `window.LayerPalette` block (no turf/DOM/Map/App, golden-tested) and an App-level cascade that reads/writes `App.*` only at call time (same rule as `choropleth.js`).

### window.LayerPalette (pure)
- `PALETTES` — 11 presets `{label, family, colors5}`: sequential `blues`/`greens`/`heat`/`viridis`/`plasma`/`inferno`/`magma`/`cividis`/`gray`, diverging `rdbu`/`quality`. Light→dark (sequential) or low→high (diverging). Only `cividis` is colorblind-safe.
- `list(allow)` → `[{id, label, family}]` filtered by family array (null = all, table order).
- `rampColors(paletteId, n, reverse)` → `n` colors subsampled from `colors5` (same arithmetic as `choropleth.js`'s `pickRampColors`); unknown id → `null`. When `n < 5`, a color whose average channel exceeds `LIGHTNESS_CEILING` (180) is darkened toward it, hue kept — otherwise Blues/Greens/Gray's near-white end is invisible on Walkshed/Travelshed's `n: 3` outer band over a light basemap (225 was tried and still too faint). `n >= 5` (TPI/RF) bypasses the clamp, so no default changed; `gradientColors()` endpoints are exempt.
- `gradientColors(from, to, n)` — channel-wise sRGB lerp (what MapLibre `interpolate linear` does). `rgba(hex, alpha)` — legend fragments need a translucent fill plus solid border from one color.
- `matchExpr(prop, colors)` → `["match", ["get", prop], 0, colors[0], …, fallback]`.
- `familyOf(id)` → `"sequential"|"diverging"|null`. `allows(spec, id)` → true when `spec.allow` is empty or includes the family — the single enforcement point keeping e.g. Corridor Scoring diverging-only.
- `CUSTOM_ID` (`"custom"`), `specFor(styleKey)` → spec | null.
- `LAYER_STYLES` — per styleKey: `walkshed`, `walkshed-seg`, `transit-travelshed`, `tpi`, `rf`, `corridor-scoring`, `gtfs-shapes`, `gtfs-stops`, `transit-coverage`, `title-vi`. Spec `{label, kind: "ramp"|"solid"|"categorical", n?, prop?, allow?, reverseDefault?, defaultColors, classes?, flattenOption?}`. `defaultColors` is an explicit array equal to exactly what the module paints with no override (keeps the default a visual no-op). `categorical` (`transit-coverage`, `title-vi`) has `classes: [{key, label}]` positional against `defaultColors` — independent semantic colors, one swatch each. `flattenOption: true` (only `walkshed`) adds a generic "Flatten overlaps" drawer row. `styleOptions: true` (`walkshed`, `transit-travelshed`) adds the drawer rows Fade outer bands and Band outlines (checkboxes), then Line weight + tone selects last; Line is disabled while Band outlines is off. Presets `gnbu`, `purples`, `ylgnbu` exist for isochrones and are not duplicated in `choropleth.js` RAMPS (only the seven noted in `layer-palettes.js` are).

### App cascade
- `App.layerStyles` — `{styleKey: {palette, reverse, color, from, to, colors, flatten, outline, outlineWeight, outlineTone, bandFade}}`; `App.mapPalette` — global palette id or null. Both persisted by `cache.js` (`layerStyles`/`mapPalette` fields).
- `App.resolveLayerColors(styleKey)` → hex array, or null for unknown key. Order: (1) per-layer override; (2) for `ramp` only, `App.mapPalette` **only if** `allows(spec, mapPalette)`; (3) `spec.defaultColors.slice()`. Solid and categorical ignore `mapPalette`.
- Ramp `reverse` defaults to `spec.reverseDefault`: `true` for Walkshed/Travelshed (dark = fewest minutes), `false` for TPI/RF/Corridor Scoring (dark = high score).
- `palette: "custom"` → `gradientColors(ov.from, ov.to, spec.n)`. **Per-layer only, never global**: not in `PALETTES`, so `list`/`familyOf`/`allows` never see it. Offered even on Corridor Scoring (two deliberate picks can't happen by accident), while the global row stays curated so one click can't make a semantic layer unreadable. Literal: `from` = first class, `to` = last, ignoring `reverseDefault` and any stale `ov.reverse`.
- `App.setLayerStyle(styleKey, patch)` — shallow-merge; deletes the entry once every field is null/absent; `App.cache.save()`; `App.repaintStyledLayers()`. `App.clearLayerStyle(styleKey)` — delete, save, repaint. `App.setLayerClassColor(styleKey, idx, color)` — the only writer of a categorical class's sparse `colors` array (pads/nulls/collapses so an all-default entry deletes).
- `App.resolveShedStyle(styleKey)` → `{outline: "merged"|"none", widthPx: 1|2|3|null, tone: "match"|"dark"|"white", bandFade}` for `styleOptions` layers. Null/absent keys mean the defaults: no band outlines, `widthPx` null = the module's own width (2 px Walkshed, 1.5 px Travelshed), tone "match". `outline: "merged"` draws one outline per time band, unioned across points. Display-only; never touches `bands[]`, study areas, exports or cache keys. `LayerPalette.withAlpha(hex, a)` / `shade(hex, amount)` are the pure color helpers. **Band fade bakes alpha into the fill COLOR** (`rgba(...)`, alphas 1 / 0.6 / 0.35 by band) rather than `fill-opacity`, because the Layers opacity slider writes `fill-opacity` directly and a color alpha multiplies with it.
- `App.registerLayerRepainter(styleKey, fn)` / `App.repaintStyledLayers(only)` — one cheap callback per consuming module, each in its own try/catch (no live layer = no-op, never blocks others). Usually paint-only; a module may re-render geometry from its own cached results (Walkshed flatten) but never recomputes the analysis.
- `App.registerLayerStyle(styleKey, spec, repaint)` / `App.unregisterLayerStyle(styleKey)` — run-time styleable layers that come and go (GeoPackage imports): register adds the spec and repainter, unregister removes the spec, repainter and any `App.layerStyles` override together.
- **Invariant:** these are the only write paths; nothing outside a module's own repainter calls `map.setPaintProperty` on a styled layer. Consumers: `choropleth.js` (`render()`'s `opts.colors`), `walkshed.js`, `transit-travelshed.js`, `transit-propensity.js`, `ridership-forecasting.js`, `corridor-scoring.js`, `transit-coverage.js`, `title-vi.js`, `gtfs.js`, the static legend fragments, and `layers-panel.js`.

## layers-panel.js

"Layers" tab of the right panel. Public API: `App.refreshLayersPanel()` (rebuilds from map state; no-op when the tab is hidden; called from the tab toggle, `App.notifyProject()`, `App.updateAddDataClearIcons()` and others) and `App.gtfsRestoreHighlight()` (re-applies the pinned GTFS highlight or clears; used by `gtfs.js`'s map right-click preview). Everything else is private. No own persistence: drawn visibility/color/opacity and `App.sectionColors` ride `cache.js`; reference/analysis order + visibility are per-session.

**Drawn feature rows** right-click menu: Zoom to feature, Hide/Show, Clear color override (when set), Edit attributes…, **Delete** (last; calls `App.deleteFeature(type, index)`, the same path as the Features list, so it is one undo step).

**Bands:** Drawn (features nested by `attributes.group`, visibility + color), Analysis overlays and Reference/Imported (declarative `ANALYSIS`/`REFERENCE` manifests keyed by MapLibre layer id; only layers present on the map render) with show/hide, opacity, drag-reorder, ⋯ menu (zoom, open module, remove), and a Basemap selector. Reorder is clamped within a band via `map.moveLayer` (drawn features stay on top; drawn groups can't z-reorder since a geometry type shares one layer). Visibility syncs both ways with the Add Data eye/× icons. Rows without a drawer get a 24px `.lp-caret-spacer` for alignment.

**Manifest notes:**
- `ANALYSIS` first entry: `bas-choropleth-fill`/`-line` ("Feature Area Analysis", `moduleId: "buffer-summary"`).
- Walkshed is two rows, `walkshed-fill` and `walkshed-seg` ("Walkshed — reachable streets"), so the streets layer hides independently.
- **Remove layer** (⋯ menu, both bands) goes through one private `removeEntry(entry)`: `App.undo.push()` → the row's clear → `App.notifyProject()` → `App.cache.save()` → `App.updateAddDataClearIcons()` → `render()` → status "Removed <label>". Reference rows use their manifest `clear`. Analysis rows default to `App.clearModule(moduleId)` and show Remove only when `App.moduleHasClear(moduleId)` (resolved at menu time, since modules register after this file). `census-geos-fill` clears `buffer-summary` (`clearModuleId`); `walkshed-seg` clears only the reachable-streets overlay via `App.clearWalkshedStreets()` (polygons stay), while removing the "Walkshed" row clears the whole module, reachable streets included. What each analysis row's Remove clears: Feature Area Analysis, Transit Propensity, Corridor Scoring, Ridership Forecast, Transit Travelshed, Transit Coverage, Walkshed, Title VI service change and FTA land-use sites each run their module's full `clear` (results, map layers and legend); Census geographies runs Feature Area Analysis's. `layer-remove.test.mjs` injects dummy layers for every entry and removes each through the ⋯ menu. Undo snapshots light state, so only rows marked `undoRestores` (Corridor Scoring, whose light state redraws its layer) add "— Undo to restore" to the status; other modules' layers come back on re-run.
- **Row extra actions.** A manifest entry may declare `extraActions: [{ label, run, status?, confirm? }]`; each becomes a ⋯ menu item after Remove layer and runs through the same private `applyEntryAction(fn, status)` sequence as Remove (undo → action → notify → save → icons → render → status), after `window.confirm(confirm)` when `confirm` is set. Street rows: "Walk network" Remove calls `App.unloadRoadNetwork()` (off the map and out of analysis, downloaded copy kept); its extra action "Delete downloaded streets" (confirmed) calls `App.clearRoadNetwork()`, which also deletes the stored copy. "Sidewalk coverage" Remove calls `App.removeSidewalkCoverageLayer()`, which drops only that overlay; the network stays loaded and the overlay returns on the next network load.
- `REFERENCE` "Walk network" row's `layers` array holds `walk-network-line`, `walk-network-excluded-line` and `network-joins-point` (opacity toggles together). "Sidewalk coverage" (`sidewalk-coverage-line`) is its **own** row right after — different semantics, hidden by default.
- `styleKey` mapping: `walkshed-fill`→`walkshed`, `walkshed-seg`→`walkshed-seg`, `ts-travelshed-fill`→`transit-travelshed`, `tpi-choropleth-fill`→`tpi`, `rf-choropleth-fill`→`rf`, `corridor-scoring-routes-layer`→`corridor-scoring`, `gtfs-shapes-layer`→`gtfs-shapes`, `gtfs-stops-layer`→`gtfs-stops`, `transit-coverage-coverage-layer`→`transit-coverage`, `tvi-impacted-fill`→`title-vi`. Feature Area Analysis, walk network, OSM, census geos, muni boundaries, road-download area and FTA sites deliberately have none.
- **Optional manifest hooks:** `entry.badge()` returns muted text (a string, or `{text, title}` — the title becomes the tooltip) rendered after the label (`.lp-row-label-indent.lp-row-badge`; hidden while the row is hovered/focused so it never covers the hover chips), and `entry.menuItems()` returns `showContextMenu` items inserted after the module/Zoom items and before Remove layer; both are wrapped in try/catch. `showContextMenu` has no disabled state, so items that don't apply are omitted. The GTFS stops entry uses both (see `modules/gtfs.md`), its `layers` array also carries `gtfs-stops-selected`, and its eye also calls `App.boxSelect.refreshBar()`.
- Toggling a styled entry's eye also calls `App.repaintStyledLayers(entry.styleKey)` so a module can react to visibility (e.g. Walkshed hides its legend's "Reachable streets" row).

**Style defaults** (below the feature list): one drawer per drawn type in use (`DRAWN_TYPES`: Points/Lines/Routes/Polygons/Buffers) with SVG preview, color swatch, `App.buildScrubber` controls over `App.featureSettings`/`App.sectionColors`, and Reset. The swatch is a live default via `App.resolveFeatureColor` — changing it recolors every non-overridden feature, not just future ones. Automatic Lines/Routes show a gradient sampled from `App.FEATURE_COLORS`; a `.lp-style-clear` × resets to Automatic.

**Points drawer extras:** an **Icon** row (`kind: "icon"`; opens `App.openPointIconPicker`, writes `App.setTypePointIcon`, × and Reset return to Dot) — see `drawing-and-features.md` § point-icons.js. Its **Width** row only affects Dot markers (tooltip says so).

**Dissolve overlaps (Buffers drawer):** a `kind: "toggle"` control (checkbox) writing `App.featureSettings.bufferMerge`. Display only — `App.buffers`/`lineBuffers`/`routeBuffers` stay one polygon per feature, so no analysis changes. When on, `App.refreshMergedBuffers()` (js/app.js) unions the display buffers per color into the `buffers-merged` source (layers `buffers-merged-fill`/`-line`, inserted just below `points-layer`, never below `buffers-fill` where analysis overlays anchor) and `App.applyFeatureOpacity("buffer")` sets the per-feature buffer layers to 0 opacity instead of hiding them — `buffers-fill`/`line-buffers-fill`/`route-buffers-fill` must stay visible for hover/click hit-testing in `editing.js`. Same-colored buffers fuse (point buffers share the point section color; line/route buffers carry `resolvedColor`); different colors still overlap. A buffer `turf.union` rejects is drawn as-is, never dropped. The merged source follows the three buffer sources through a `sourcedata` listener (their modules re-render through closure-local functions that bypass any `App.*` wrapper), coalesced per tick and skipped when the buffers are identical to the last union. Saved/restored/reset with the other `featureSettings` in `cache.js`; absent in old sessions = off. Test: `test/browser/buffer-merge.test.mjs`.

**Per-feature overrides:** each feature row's caret opens a drawer built by `App.buildFeatureOverrideRows` (shared with the Appearance popover; no Buffer row — radius lives in `App.buildBufferRadiusControl`). The row's type-icon swatch opens `App.openAppearancePopup` and gains a `.lp-style-clear` × when `properties.color` is set (resets to `""` = inherit).

**Analysis/reference style drawers:** `buildLayerRow()` wraps styled rows in `.lp-style-group`/`.lp-style-drawer`. `buildLayerStyleDrawer()`:
- `ramp`: Palette select (`Default` + `LayerPalette.list(spec.allow)` + `Custom`) and Reverse checkbox (disabled while Default); "Flatten overlaps" when `spec.flattenOption`; Reset clears via `App.clearLayerStyle`. Choosing Custom swaps Reverse for two endpoint swatches seeded from the currently resolved first/last colors (a visual no-op).
- `solid`: `.lp-swatch` → `App.openColorPicker` + × once overridden.
- `categorical`: one label + swatch + × per class, via `App.setLayerClassColor`.
- A global palette row (`buildGlobalPaletteRow()`) tops the Analysis band: `Default` + all palettes; sets `App.mapPalette`, saves, repaints. Selects reuse `.lp-basemap-select`.
- **Every control writes through `App.setLayerStyle`/`App.clearLayerStyle`/`App.setLayerClassColor` — never `map.setPaintProperty`.**

**GTFS route browser** (`docs/archive/gtfs-route-browser-plan.md`): the "GTFS routes" row gets a caret (`decorateGtfsRow`) opening a filter (`.lp-gtfs-filter`, `App.gtfsBrowse.filterRoutes`), Show all / Hide all / Show only filtered, and up to 200 route rows (then "Showing 200 of N"). Shape rows build lazily. Hover/focus → `App.gtfsHighlight`; click pins (double-click pins + zooms); eye → `gtfsSetRouteHidden`/`gtfsSetShapeHidden`; ⋯/right-click/ContextMenu/Shift+F10 → `App.showContextMenu` (copy as line / each shape / grouped Service, show only, zoom). Copies then `App.selectFeature("line", firstNewIndex)`. UI state `_gtfsUI` survives `render()`, which also preserves scroll and filter focus; a new feed resets it; nothing renders when `App.gtfsRouteIndex()` is null. Styles `.lp-gtfs-*`.

**Runtime reference rows:** GeoPackage imports are the only reference rows that come and go at run time. `referenceEntries()` in `js/core/layers-panel.js` adds `App.gpkgReferenceEntries()` to the static `REFERENCE` entries on each render, using the same entry shape (`id`, `label`, `layers: [{id, op}]`, `styleKey`, `clear`, `menuItems`, `badge`), plus two optional fields any entry may use: `displayLabel` (shown instead of `label`, which stays as the hover text; GeoPackage rows show `<layer> · <file>`) and `bbox()` (Zoom to layer's extent). A new import's row is placed in the band where its layers sit on the map, and a removed import's id is dropped from the band order. Built-in rows stay in the static manifest.

Also uses: `App.rerenderForType`, `App._openFpSlider`, `App.applyFeatureOpacity`, `App.applyLineWidth`, `App.applyBufferLineWidth`, `App._polyOpacityValues`, basemap API, `properties.hidden`.

## GeoPackage import (gpkg-reader.js / gpkg-layers.js / gpkg-table.js / gpkg-store.js)

Add Data → **GeoPackage (.gpkg)…** (button `ad-gpkg`), or the general Import file picker (`#fp-import-file`, routed by extension in `js/app.js`), opens a layer picker (`#gp-dialog`). Each checked feature table becomes a **view-only reference layer** in the Layers panel's Reference band, labelled `<file name> · <table>`. Imported layers are not drawn features: they stay out of `App.points/lines/routes/polygons`, have no Features-panel rows and are not analysis inputs. Each layer row has show/hide, opacity, drag-reorder, Zoom to layer, Remove layer and a color drawer. A checked table without geometry is kept as a table instead of a layer (see **Tables without geometry** below).

- `js/core/gpkg-reader.js` — `window.GpkgReader`: pure blob/WKB → GeoJSON, projection rules, row → properties, and the number and cell-text helpers used by the color ramp and the table viewer. No DOM, map or sql.js.
- `js/core/gpkg-layers.js` — library loader, sql.js reading, picker flow, map layers, color ramp, tables, registry, click popup and startup restore.
- `js/core/gpkg-table.js` — the attribute-table window (`App.gpkgOpenTable`, `App.gpkgCloseTable`). It knows nothing about GeoPackage internals.
- `js/core/gpkg-store.js` — IndexedDB copy of the original file bytes (see Persistence).

**Libraries.** sql.js 1.10.3 and proj4 2.11.0 are loaded from cdnjs on the first open, not from `index.html`. The sql.js WASM is fetched first and passed in as `wasmBinary`, because sql.js never settles when its own fetch fails. A failed load rejects with one message and the next open tries again. Offline tests use copies in `test/ui-screens/vendor/` (`sql-wasm.js`, `sql-wasm.wasm`, `proj4.js`), mapped by `VENDOR_MAP` in `test/browser/harness.mjs`.

**Reading.** Feature layers are `gpkg_contents` rows with `data_type = 'features'`, joined to `gpkg_geometry_columns`. Raster tile tables are listed as "Raster tiles are not supported". Attribute tables, and feature tables with no geometry column, become tables (see below). Any other type is listed as "Not supported (<type>)". A file without `gpkg_geometry_columns` is still listed. A layer that fails while it is inspected is listed as unsupported and does not abort the file. Rows are read one at a time with a prepared statement.

**Projection** (`GpkgReader.resolveProjection`, first match wins). Nothing is imported untransformed; a refused layer is listed with its reason.
- srs_id 4326, EPSG 4326 or 4269, or OGC CRS84 → used as-is (labelled WGS 84 or NAD83).
- EPSG 3857 or 900913 → Web Mercator through proj4.
- Built in, no lookup: NAD83 UTM 26901–26923; WGS 84 UTM 32601–32660 (north) and 32701–32760 (south).
- Otherwise a non-empty stored definition (not `"undefined"`) → the file's WKT through proj4. `AXIS[...]` clauses are stripped so x/y stay easting/longitude. Refused as "Unknown projection (org:code)" if proj4 throws or an envelope corner falls outside lon/lat.
- srs_id −1 or 0 with no usable definition → treated as lon/lat only if the envelope lies within −180..180 × −90..90; otherwise refused.
- Anything else → refused as "Unknown projection (org:code)".

**Geometry.** ISO and EWKB Z/M/SRID forms are read and Z/M are dropped, so every coordinate is `[x, y]`. Skipped and counted in the import status: empty and NULL geometries (`empty`, `nullGeom`), GeometryCollections (`collection`), curve and surface types, extended blobs and Multi* members of the wrong type (`unsupported`), and shapes that fail a bounds check (rings under 4 points, lines under 2, non-finite values) or a transform (`invalid`). Attributes are every column except the geometry and a single integer primary key; BOOLEAN 0/1 becomes true/false, BLOB columns are dropped and NULL is omitted. The feature id is the integer primary key when there is one, otherwise the row number.

**Map layers.** One GeoJSON source `gpkg-src-gpkgN` per import, where N counts from 1 on each page load. Layers `gpkg-gpkgN-fill` and `-outline` (polygons), `-line` (lines) and `-point` (points), each filtered by geometry type, only for the kinds present. They are added bottom to top directly below the drawn-feature layers via `App.firstUserLayer()`. Transparency lives in the fill color (`FILL_ALPHA` 0.35 through `LayerPalette.withAlpha`), so every opacity starts at 1 and the row's slider reads 100% for "as imported". Colors come from a fixed list of eight in `gpkg-layers.js`, taking the first one no other import uses. A layer with no drawable features gets no source and no row.

**Styling.** Each import registers a run-time `solid` spec with `App.registerLayerStyle("gpkg-gpkgN", { label, kind: "solid", defaultColors: [color] }, repaint)` (`js/core/layer-palettes.js`). The drawer writes `App.layerStyles["gpkg-gpkgN"]` through `App.setLayerStyle`, and the repainter sets the paint properties. Removal calls `App.unregisterLayerStyle`. A new import first deletes any stale override under its key, because ids restart at gpkg1 on each page load. A color picked in the drawer replaces the color ramp below, and resetting the color brings the ramp back.

**Filter and fill transparency (API).** Each layer's filter (`window.GpkgFilter`, `js/core/gpkg-filter.js`), fill transparency and display name live on its registry record, not in `App.layerStyles`, and are saved with the file as the store record's `views`. Only features matching the filter are drawn, counted in the badge (`N of M`), fitted by Zoom to layer (the entry's `bbox()` hook) and copied to drawn features.
- `App.gpkgGetLayerState(id)` → `{ id, label, table, fileName, columns, filter, fillAlpha, hasPolygons, featureCount, matchCount }`, or `null` for an unknown import id (`gpkgN`).
- `App.gpkgSetLayerFilter(id, filter)` normalizes and applies a filter (`null` clears it), refreshes the panel and saves.
- `App.gpkgSetFillAlpha(id, alpha)` sets the fill's alpha (0–1, steps of 0.05; default 0.35) and saves; the row's opacity slider still scales fill and outline together.
- `App.gpkgFieldValues(id, field)` → `GpkgFilter.distinctValues` over the layer's rows (first 200 distinct values), cached per field.
- `App.gpkgBuildLayerControls(body, ctx)` (`js/core/gpkg-filter-ui.js`) appends the drawer's Fill and Filter rows and reports changes through `ctx.onFillAlpha` and `ctx.onFilter`; it keeps no state and never touches the map.

**Filters.** A feature layer can show only the features that match its filter. The filter is a list of conditions, and a feature must match every one (AND). It is set in the layer's color drawer, in the **Filter** block under the Fill row. Each condition takes two lines: the field and operator on the first, the value box on the second. The field list holds the table's columns. The last row is always blank, ready for a new condition; a row with no field or value is ignored rather than reported as an error. Changing the field or operator applies at once; the value box applies when its value changes (Enter, or leaving the box). **Clear filter** removes the whole filter.

Operators (`GpkgFilter.OPS`, in this order). Text comparisons use the text form of a value: a number prints as stored (`600` matches `600`), a boolean as `true` or `false`, and a null as empty.

| Operator | Matches |
|---|---|
| is | text equals the value exactly, case-sensitive |
| is not | text differs from the value |
| is one of | text equals one of the comma-separated values |
| contains | text contains the value, ignoring case |
| is greater than, is at least, is less than, is at most | the value is a number and the comparison holds (see limitations) |
| is blank, is not blank | text is empty, or not empty; no value box |

The table's **Show matching on map** button (feature layers only) adds one condition to the existing ones: any column contains its search text. The table then reopens with the rows the map now shows. This "Any column" condition exists only this way; the drawer's field list does not offer it, though a condition the button made keeps it in the field list.

The badge shows `N of M` (M is every feature in the layer), and its tooltip adds the filter, for example `· filter: polygon_id is denver-25ft-blocks_2020`. The drawer's Filter heading reads "N of M shown". Zoom to layer fits the matching features; when none match, the status reads "No features match this layer's filter". Copy to drawn features copies only the matching features (the menu reads "Copy N shown features to drawn features"). The attribute table lists only the matching rows, and its count line adds "· map filter: <describe>". Hidden features are not drawn, so they cannot be clicked.

**Fill transparency.** Polygon layers have a **Fill** row at the top of the color drawer: a scrubber from 0 to 100 % in steps of 5. It changes only the fill's alpha, so the outline stays solid. The default is 35 %, the fixed value used before this option existed. The row's opacity slider still scales fill and outline together, so Fill 0 % at 100 % opacity gives a clear fill with a solid outline. The value is kept as `fillAlpha` (0–1, steps of 0.05) on the record, and a missing or non-numeric value falls back to the default. The drawer's scrubber repaints the layer without re-rendering the panel, so a drag is not interrupted; `App.gpkgSetFillAlpha` also re-renders the panel.

**Duplicates and names.** ⋯ → **Duplicate layer** adds a second view of the same table. The two views share one GeoJSON source, so the file is not loaded or stored twice. The copy takes the original's filter and fill, gets the next unused color, and is added at the top of the Reference band. Each view then keeps its own color, filter, fill and name. Its name is `<table> (n)`, where n is the lowest number that no view of that table already uses, so after `(2)` is removed, the next duplicate is `(2)` again. Removing the original keeps the duplicate drawn; the shared source is removed only with its last view.

⋯ → **Rename…** opens the browser's prompt. The name replaces the table name in the row (shown as `<file> · <name>`), in the table window's title and in the popup title. An empty name, or the table's own name, clears the name. Names are display only: the store and the file's table list still use the table name.

**Persistence of views.** The store record has a `views` array, oldest first, with one entry per view: `{ table, label, base, color, filter, fillAlpha }`. `label` is `null` when the view has no name, and `filter` is `null` when it has no filter. `base` is the import's own color and `color` the current one. `layers` and `colors` are still written beside `views`, so an older build reads the same record. Restore reads each table once: the first view of a table is read from the file, and each later view is added as a duplicate of it, with its saved color, filter, fill and name. A view that fails to restore is skipped, and the others still restore. A record saved before views existed has no `views`; it restores as before, with one layer per table, no filter, the default fill and the table name. Filter and fill changes save after a 400 ms pause, as color changes do; a duplicate or rename saves at once. Saves wait until the restore ends, so a restore never writes a partial set of views.

**Color ramp.** A feature layer is colored by a travel-time or cost column when it has one. `GpkgReader.pickColorField` picks the first column, in the table's column order (from `PRAGMA table_info`, passed through `_readLayer`), whose name matches `/(second|minute|^sec|_sec|time|cost)/i` and that has at least one numeric value (numeric text such as `"125.5"` counts). Values run green (`#1a9850`) → red (`#d73027`) over the column's min..max through five color stops. Features with no value are gray (`#9aa0a6`), and a column whose values are all equal (or whose range is too small for MapLibre's strictly ascending stops) is drawn green. A color picked in the layer's style drawer replaces the ramp (the badge then drops the "colored by" text); Reset brings the ramp back. Each feature's value is copied into a private `_gpkgColor` property that the paint expression reads. Properties starting with `_gpkg` are hidden from popups, the table viewer and copies to drawn features. The ramp is worked out again from the file on restore and is not saved. The layer's badge tooltip names the field and range, for example "12 features · colored by travel_minutes (0 green → 45 red; gray = no value)".

**Click popup.** One map click handler, wired on the first import. The popup opens only when a `gpkg-` layer is the topmost rendered feature, no tool is active (`App.drawMode` is null; drawing, measure, box select and split pick all set it), and no OSM, walk-network or network-join layer is under the pointer, since those have their own click handlers. If nothing is under the pointer, the click is retried in a 5 px box around it (`CLICK_TOLERANCE_PX`) that counts only GeoPackage features, so thin lines and small points are easy to hit. The title is file and table; each attribute is a row, and JSON object or array text is shown as a nested list. A click on a GeoPackage feature still clears the drawn-feature selection (editing.js treats it as an empty-map click). Blocking it would leave no way to deselect when an import covers the study area. The hover cursor is a pointer.

**Copy to drawn features.** The layer's ⋯ menu offers "Copy to drawn features" when the layer converts to 2,000 drawn features or fewer (Multi* parts count; only those layers keep their features in memory). It calls `App.cache.appendGeoJSONFeatures(features)` (`js/core/cache.js`), which returns `{ added }` or `{ added: 0, error }`. Copies are appended and never replace drawn features. They are deep copies, so edits to them never reach the import, and they form one undo step. Nothing is selected afterwards.

**Tables without geometry.** Attribute tables, and feature tables with no geometry column, are listed in the picker as "Table (no map layer) · N rows" and can be checked; they start unchecked, since files often carry bookkeeping tables (QGIS's `layer_styles`) nobody means to open. Up to 20,000 rows are read (`MAX_TABLE_ROWS` in `gpkg-layers.js`); the picker shows the full count. Every column is kept with its stored values, and BLOB cells show as "(binary, N bytes)". A table belongs to its file: each layer of that file offers "View table: <name>" in its ⋯ menu. Tables are stored and restored with the file, and they are dropped when the file's last layer is removed or on Clear. A file with tables and no map layers keeps none, since no Layers row could reopen them: the first checked table is shown once, and the status says the others show when the file is opened again.

**Attribute table viewer.** ⋯ → "View attribute table" on a feature layer lists its features, one row each, with the union of their attributes as columns. ⋯ → "View table: <name>" opens a table. Both use `App.gpkgOpenTable` in `js/core/gpkg-table.js`: a window with widget id `gpkg-table`, bottom-left, 560 px wide, titled "<name> — <file name>". Opening one replaces any open window. The filter box matches any column, case-insensitively, 150 ms after typing; keys typed in it do not reach the app's shortcuts. The count line reads "N rows" or "N matching rows", then "showing first 500" when the first 500 are drawn, then "file has T, only L loaded" when a table was capped at 20,000 rows. On a feature layer, clicking a row marks it, zooms to that feature and opens its popup; a plain table has no row click. The window closes when the layer it shows is removed, when the last layer of the file holding an open table is removed, and on Clear. Its × removes the window (not just hides it, as other floating widgets do), so a large layer's rows are freed.

**Opening.** Files over 200 MB ask first. One file opens at a time; a second attempt shows a status message. Layers are read one at a time with a yield between them so the progress text shows. Escape and Cancel close the picker, and the picker stops Escape in the capture phase, as the attributes dock does. After an import that adds layers, the map fits them and the right panel switches to the Layers tab.

**Persistence** (`App.gpkgStore`, `js/core/gpkg-store.js`). IndexedDB database `mat-gpkg-cache`, store `files`, keyed by `"<file name>|<byte size>"`. Record: `{ name, savedAt, size, bytes, layers: [names of every checked layer and table], colors: { table: { base, color } }, views }`, where `base` is the import's own color and `color` is the current one (`views` is described under **Persistence of views**). Limits: 3 files and 100 MB in total, oldest dropped first; a single file over 100 MB is not stored. Writes happen on import, on Remove layer (`update`, which deletes the record when no layers are left) and on a color, filter or fill change (debounced 400 ms; a duplicate or rename saves at once). Toolbar Clear empties the store even when nothing is on screen.

`App.restoreCachedGpkg()` runs from `js/app.js` after the GTFS restore. It opens the oldest file first and re-runs the normal open → read → add path, so a restored layer matches a fresh import. Restored layers start visible with their saved colors. A file that no longer opens is dropped from the store. Offline at startup, the files are kept for the next refresh.

**Not saved in session JSON or share links**, same as GTFS. A recolor override does sit in `App.layerStyles` (so it can appear in session JSON) until its layer is removed.

**Clear All.** Toolbar Clear calls `App.gpkgClearAll()`, as it does for GTFS: it removes every import and empties the store.

**Public API**
- `App.gpkgOpenFile(file)` — entry point from Add Data and the Import picker; returns a Promise.
- `App.gpkgReferenceEntries()` — Layers-panel entries, newest first, in the `REFERENCE` shape. `clear` removes the layer, `menuItems` adds the table entries and Copy to drawn features, and `badge` shows the feature count (with the ramp field and range in its tooltip when a ramp applies).
- `App.gpkgRemoveLayer(id)` — removes one import's layers, source and style, then updates the store.
- `App.gpkgClearAll()` — removes every import and empties the store.
- `App.gpkgLoaded()` — true when at least one import is loaded (the Add Data row's state).
- `App.gpkgVisible()` / `App.gpkgSetVisible(v)` — the Add Data eye. Hiding also closes an open popup.
- `App.restoreCachedGpkg()` — startup restore; resolves to the number of layers restored.
- `App.gpkgStore` — `{ supported, save(key, bytes, layers, colors, views), list (newest first), update(key, layers, colors, views), remove, clear, MAX_ENTRIES, MAX_BYTES }`. `views` is optional; when it is omitted the record keeps none.
- `App.gpkgOpenTable({ title, columns, rows, total, onRowClick })` — the attribute-table window (`js/core/gpkg-table.js`). `rows` are plain objects; `onRowClick(rowIndex)`, or `null` for no row click (no hint line). Replaces any open table window; returns a Promise.
- `App.gpkgCloseTable()` — removes the table window if it is open.
- `window.GpkgReader` — `parseGeometryBlob(bytes)`, `wkbToGeoJSON(view, offset)`, `rowToProperties(columns, values)`, `resolveProjection(srsRow, envelope)`, `transformGeometry(geometry, fn)`, `numericValue(v)`, `pickColorField(columns, rows)`, `formatValue(v)`. The `parseGeometryHex`, `rowToPropertiesJSON`, `tryParseGeometryHex`, `wkbHexToGeoJSON` and `transformGeometryAffine` wrappers exist for golden tests only.
- `App._gpkgTest` — test-only hook (exists only when `window.__MAT_TEST__` is set, as in core-app.md): `loadLibs`, `openDb`, `inspect`, `readLayer`, `addLayerToMap`.

**Known limitations**
- Raster tiles, grid-shift projections and WKT2 nested AXIS clauses are not supported.
- Escape does not close the picker while the box select tool is active (box-select.js handles Escape first).
- Hiding a layer with its Layers-panel eye does not close an open popup (the Add Data eye does).
- The pointer cursor shows over a GeoPackage layer even where another layer takes the click.
- The 5 px click retry runs only when nothing at all is under the pointer, so it does not help over an analysis fill or a drawn buffer.
- Remove layer's undo step cannot bring an import back (as with GTFS).
- Numeric comparisons (is greater than, is at least, is less than, is at most) compare real numbers only. A value stored as text, such as `"125"`, does not match them, though `is` and `contains` still match it. The map expression follows the same rule, so the map and the matcher agree.
- The attribute table's search matches the text it shows, which rounds numbers to 3 decimals, while the map filter compares the full value. **Show matching on map** can therefore match fewer rows than the table search showed. The table then reopens with the rows the map shows.
- Value suggestions list the first 200 distinct values in sorted order, with no hint that more exist. A value beyond them can still be typed.
- Changing an existing condition into an invalid state, such as switching `is` to `is greater than` while the value box holds text that is not a number, drops that row (the other conditions stay) when the drawer re-renders.
