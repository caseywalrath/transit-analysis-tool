# Drawing and features

Reference for the drawing, editing, feature-panel, appearance, attribute, merge and split code. Read the code when this and the code disagree.

## points.js
Points, per-type buffers (default 0.5 mi), union polygon, point drag. Exports: `points`, `buffers`, `addPoint(lon, lat)`, `addPointWithOpts(lon, lat, opts)`, `rebuildBuffers(radiusMiles)`, `refreshBuffers()` (rebuild at the current radius; used by Walkshed), `movePoint(index, lng, lat)`, `removePoint(index)`, `clearPoints()`, `undoLastPoint()`, `duplicatePoint(index)`, `renderPointLayers()`, `bufferUnionPolygon()`, `getUnion()` (alias), `bboxStringFromFeature(feat)`.

`rebuildBuffers()` substitutes the cached walkshed when `attributes.serviceAreaType === "walkshed"` and `App.getPointWalkshed(pointIdx)` returns one (else the circle); that `buffers[i]` carries `properties.walkshed = true`.

## lines.js
Polylines with snap-to-close, rubber-band preview, vertex editing, buffers (default 0.5 mi). Exports: `lines`, `lineBuffers`, `handleLineClick(lngLat)`, `rebuildLineBuffers(radiusMiles)`, `lineBufferUnionPolygon()`, `removeLine(index)`, `clearLines()`, `undoLastLine()`, `cancelLineDrawing()`, `renderLineLayers()`, `setLinePreview(lngLat)`, `updateLineVertex(lineIndex, vertexIndex, lng, lat)`, `duplicateLine(index)` (copies color + appearance overrides via `App.copyAppearanceOverrides`, never `_mergedFrom`).

Saved lines render in three layers on source `lines`: `lines-layer` (solid), `lines-layer-dashed` (`[4, 2.5]`), `lines-layer-dotted` (`[0, 2]` + round cap), filtered on `properties._lineStyle` (utils.js line-style helpers). `App.applyFeatureOpacity`/`applyLineWidth` paint all three; `line-offset` is set on all three at creation.

## routes.js
OSRM street-snapped routes. Exports: `routes`, `routeBuffers`, `handleRouteClick(lngLat)`, `setRoutePreview(lngLat)`, `rebuildRouteBuffers(radiusMiles)`, `routeBufferUnionPolygon()`, `removeRoute(index)`, `clearRoutes()`, `undoLastRoute()`, `cancelRouteDrawing()`, `renderRouteLayers()`, `updateRouteWaypoint(routeIndex, waypointIndex, lng, lat)`, `duplicateRoute(index)` (like `duplicateLine`), `fetchRouteGeometry(waypoints)` → `Promise<coords | null>` — same router as drawing (local network via `App.findLocalRoute` when loaded, then OSRM `https://router.project-osrm.org/route/v1/driving/`); `null` = caller draws a straight line (it also posts the "using straight line" status). Used by Feature Merge for route connectors.

`properties.waypoints` (user clicks) is stored separately from the snapped `geometry.coordinates`; vertex handles are on waypoints only. Preview: straight line immediately, snapped after ~1 s idle (AbortController cancels stale fetches). Rendered in `routes-layer` / `-dashed` / `-dotted`, like lines.

## polygons.js
Vertex-by-vertex with snap-to-close. Exports: `polygons`, `handlePolygonClick(lngLat)`, `removePolygon(index)`, `clearPolygons()`, `undoLastPolygon()`, `cancelPolygonDrawing()`, `renderPolygonLayers()`, `setPolygonPreview(lngLat)`, `updatePolygonVertex(polyIndex, vertexIndex, lng, lat)`.

## editing.js
Point drag, line/polygon/route vertex editing (orange handles). Exports `_editing` (state or null), `exitEditMode()`, `_initEditing()` (called from app.js on map load).
- Every hit test queries `App.lineStyleLayerIds()` and classifies with `App.lineStyleLayerType(layerId)` so dashed/dotted features behave like solid ones. Drag previews copy all properties (incl. `_lineStyle`).
- **Map right-click menu** single-selects, except right-clicking a member of a 2+ selection keeps it and shows `App.bulkFeatures.groupMenuItems` (with Merge… when mergeable). Also runs while `App.drawMode === "box-select"`. Single-feature items: Attributes, Duplicate, Split here, Split out section…, **Unmerge…** (only when `App.merge.hasHistory`, opens `App.merge.openUnmergeDialog`), Hide/Show, Delete.

## features.js
Right-side panel: editable names, type icons tinted with the resolved color (click opens the Appearance popover), gear opens the attributes popup, row click selects on map only, trash with inline confirm strip. Header is a `Features | Layers` tab bar (`#fp-tab-features` / `#fp-tab-layers`); showing Layers calls `App.refreshLayersPanel()`. A Line with `attributes.networkRole === "connector"` gets a muted `.fp-net-chip` ("walk").
- **Right-click menu:** single selection → Attributes, …, Unmerge… (before Hide/Show, only with `properties._mergedFrom`, never on multi-selection). 2+ selection → `App.bulkFeatures` items (Zoom to selection, Merge…, Hide N, Delete N features…) before Group…/Ungroup. **Merge… exists only here** (the right-clicked row is the default primary via `primaryFor`); the map menu and Layers rows are single-select.
- **Sorting** (`#fp-sort-btn` or header right-click): Name/Type/Date added/Group, asc/desc, show groups. Display-only — never reorders `App.points`/`lines`/`routes`/`polygons` or draw order. Labels and Text always sort by name.
- Exports: `refreshFeaturePanel()`, `rerenderForType(type)`, `getTypeDefaultColor(type)`, `updateFeatureColor`, `App.collectDrawnFeatures()` → `[{feature, type, index}]` (shared with Layers), `UNIVERSAL_GROUP_KEY`.
- `showContextMenu(x, y, options)` closes on the next outside press or Escape (listeners attach immediately, not after a timer); `App.closeContextMenu()`. Items may carry optional `onHover(isEntering)` — false also fires when the menu closes by any path while hovered.
- `openColorPicker(anchorEl, color, onChange)` wraps `buildColorPickerBody(currentColor, onPick)` — the one picker body (also embedded by the Appearance popover), so a change applies to every picker (see docs/archive/color-picker-variety-plan.md). 50-swatch `PICKER_COLORS` grid (data colors, exempt from design tokens), a **Recent** row (max 10), hex entry, and **Custom…** (hidden `<input type=color>`; only `change` commits, so one choice = one `onPick` = one undo step). All pick paths go through one `pick()` that records Recent. Recent is per-browser, NOT session state: `localStorage` `mat-recent-colors` (try/catch), seeded from colors in use via `App.resolveFeatureColor`. Body exposes `setColor(c)` and `refreshRecent()`.

## box-select.js
Loads right after `selection.js` (see docs/archive/box-select-plan.md; smoke test `test/box-select-smoke.mjs`).
- `App.boxSelectGeom` — pure pixel hit-tests (golden: `test/cases/box-select.mjs`): `normRect`, `pointInRect`, `segmentIntersectsRect`, `pointInRing`, `bboxOf`, `bboxIntersectsRect`, `lineHits(pts, rect, mode)`, `polygonHits(rings, rect, mode)`, `mode` `"touch"|"within"`.
- Tool active while `App.drawMode === "box-select"` (toolbar button or `A`; entering does NOT clear selection). Mouse events are intercepted on `window` in capture phase, so MapLibre never sees them — no `dragPan` to restore; wheel and right-click pass through. Release: plain = replace, Shift = add, Ctrl/Cmd = remove, Alt = fully inside; applied via `App.setSelection`. A drag < 4 px acts as a click. Escape cancels a drag, else exits.
- Shift+drag with no tool active also box-selects (replace); MapLibre box zoom is disabled (`boxZoom: false` in `map.js`) for this.
- `App.boxSelect = { isActive, isDragging, cancel }`.
- `App.bulkFeatures` (`usable`, `describe`, `anyVisible`, `setHidden`, `remove`, `confirmRemove` (`.fm-*` dialog, one undo step), `zoomTo`, `groupMenuItems(list, mergeItem)`) — shared by editing.js, features.js and the Delete key in app.js; labels ignored.

## feature-appearance.js
Loads after `features.js`, before `feature-attributes.js`/`layers-panel.js` (see docs/archive/feature-appearance-plan.md; smoke test `test/feature-appearance-smoke.mjs`).
- `App.openAppearancePopup(anchorEl, type, index, opts)` — singleton `#fp-appearance-popover`: Color (via `App.buildColorPickerBody`), Opacity / Weight / Offset, Line style (lines/routes), **Reset all** (one snapshot via `App.undo.batch`). Opened from the Features-pane icon, Attributes header swatch, Layers feature swatch and Attribute Summary swatch; labels/text boxes use plain `App.openColorPicker`. `opts.onChange()` refreshes the caller's swatch. Re-opening on the same feature toggles closed (keyed by feature, since panel refreshes rebuild the swatch). `App.closeAppearancePopup()`, `App.isAppearancePopupOpen()`.
- No Buffer row: buffer radius is study-area geometry (Attributes popup).
- `App.buildFeatureOverrideRows(type, feature, {onChange})` → DOM rows — **the single implementation** of the "muted default until overridden, × clears" rows, used by the popover and the Layers per-feature drawer. Polygon opacity writes `_fillOpacity`+`_borderOpacity` via `App._polyOpacityValues`; offset writes `_offset`+`_offsetManual`, its × re-runs `App.computeOverlapOffsets()` when `#offsetOverlap` is checked.
- **Line style** reads `App.normalizeLineStyle(properties._lineStyle)` and writes ONLY through `App.setFeatureLineStyle` — never set `_lineStyle` directly from UI code.
- Features are held as `{type, id}` refs resolved on every read/write (`App.featureById`), so undo/redo/merge/delete can never write to a stale object; the popover closes if the feature is gone and rebuilds after Ctrl/Cmd+Z/Y.
- **Undo = one snapshot per gesture**: each row arms a flag on mousedown/click/change (capture phase); the first commit after it takes the snapshot.

## feature-attributes.js
Singleton popup `#fp-attr-popup` (fixed, z-index 9000, 320 px, docked at left 24 px / top 60 px on a fresh open, draggable by header and clamped to keep ≥40 px visible, collapsible, Escape/X close). Exports: `openAttrPopup(featureType, featureIndex, feature)` (same feature = toggle close; different feature = replace in place, keeping position), `closeAttrPopup()`, `isAttrPopupOpen()`, `getAttrPopupFeature()` → `{featureType, featureIndex}` | null. `selection.js selectFeature()` re-targets an open popup.
- `ATTR_FIELDS` per type; attributes live in `properties.attributes` (lazy-init, so old sessions restore cleanly). **Any schema change must be mirrored in `js/projects/attribute-summary.js` and the `.as-grid-*` templates in `css/style.css`.**
- Route/line: group, direction (Both/NB/SB/EB/WB/Inbound/Outbound/Loop/CW/CCW), mode, `serviceId`, `avgSpeed` (default 14 mph, seeded on lazy-init), service bands (weekday/saturday/sunday), notes. Polygon: group, notes. Point: group, stopId, associatedRoutes, then Study area (`serviceAreaType` `""`|`"walkshed"` — change fires `App.ensurePointWalksheds()` + `App.refreshBuffers()` + `App.notifyProject()`; then bufferRadius).
- A field may carry `section: "<label>"` (emits `.fp-attr-section` header), `optionLabels`, and `onChange(attrs)`. `TRANSIT_FIELDS` (section "Transit service") is shared: `ROUTE_FIELDS` = it + `bufferRadius`; `LINE_FIELDS` = it + `networkRole` (`""`|`"connector"`, section "Walk network", onChange calls `App.refreshNetworkConnectors()`) + `bufferRadius`. Routes get no `networkRole` — they already follow streets.
- **Service pairing:** `serviceId` (replaced the old `routeId`) groups routes/lines into one Service (1, 2 or 3+ patterns) for Route Costing/Trip Builder; 2-pattern Services need opposite directions (NB+SB, EB+WB, Inbound+Outbound, CW+CCW); in 3+ every pattern needs a one-way direction (not `Both`/blank). Autocomplete datalist `fp-service-datalist`. `group` has no Costing semantics. RF/CDI code still treats each feature as its own route.
- **Buffer radius:** `App.buildBufferRadiusControl(type, feature, {note})` — single implementation shared with the Attribute Summary Buffer column. Reads/writes **`properties._bufferRadius`, never `attributes`**; shows the type default (`App.featureSettings.bufferRadius`/`lineBufferRadius`/`routeBufferRadius`) muted until overridden. Buffers rebuild live per scrub tick (`App.rebuildBuffersForType(type)`), but undo snapshot, `App.cache.save()` and `App.notifyProject()` fire once per gesture. Disabled on walkshed points; `App.refreshBufferRadiusControls()` re-syncs (called from `onServiceAreaChange`). Holds a `{type, id}` ref.
- `App.refreshAttrPopupSwatch()` re-syncs the header swatch (called by the Appearance popover). The old override icon strip / `App.buildOverrideIcons` was retired.
- Shared helpers (popup + Attribute Summary + Trip Builder): `App.openTimeBandsPopup(feature, anchor, onChange)`, `App.openRoutePickerPopup(attrs, anchor, onChange)` (mutates `attrs.associatedRoutes`), `App.buildPointRouteBadge(pointFeature)` (`.fp-route-badge`), `App.buildTimeBandsBadge(feature)` (`.fp-bands-badge`, e.g. "3 · 1 · 0"), `App.openMiniPopup({title, content, anchor, onClose})` / `App.closeMiniPopup()`, `App.buildServiceScheduleEditor(feature)`. `#fp-mini-popup` is a separate singleton (z-index 9100, draggable, Escape closes) so it can coexist with `#fp-attr-popup`.

## merge.js
Loads after `feature-attributes.js` and before `attribute-summary.js` (which delegates to `App.mergeAttrs.fieldHasValue`). See docs/archive/feature-merge-plan.md; smoke test `test/feature-merge-smoke.mjs`.
- **Pure helpers** (golden: `test/cases/merge.mjs`): `App.mergeGeom.chainLines`, `App.mergeGeom.findBranch`, `App.mergeGeom.lengthMi`, `App.mergeGeom.planRouteChain`/`assembleChain`/`routeChain` (greedy nearest-endpoint chaining; a join < ~1 m drops the duplicate vertex; branch tolerance ~50 ft); `App.mergeAttrs.{hasValue, fieldHasValue(kind, v), mergeAttributes(items, primaryPos, {kind}), reversalWarnings(items, chain)}` — primary wins, blanks filled, notes joined, line `runTime` summed / `avgSpeed` length-weighted; points: `associatedRoutes` unioned by featureType+featureId, conflicting `stopId` warns, `serviceAreaType` primary-only (blank is a real choice); `App.mergeHistory.{stableStringify, fingerprintFeature, stopChanges, restoreStopRefs, validateHistory, stripHistory}`.
- `STRATEGIES` per type (`line`, `route`, `point`, `polygon`, `linemix`): synchronous `analyze()` → plan `{ok, errors, warnings, summary, discarded, survivor, removed, removedIds, stopsRepointed, apply, repoint, prepare?}`; `prepare` (routes only) street-routes connectors via `App.fetchRouteGeometry` sequentially, straight on failure, only when the user clicks Merge.
- API: `App.merge.mergeableSelection(selected)` → `{type, indices, primaryFor(featureType, featureIndex)}` | null (all one type, or lines+routes → `"linemix"` with `{type,index}` refs; anything else rejected); `App.merge.analyze(type, indices, primary)`; `App.merge.run(type, indices, primary, {isCancelled, onProgress})` → `Promise<{ok, survivorType, survivorIndex, removedIds, repoints, routing, message} | {ok:false, errors} | {ok:false, cancelled:true}>`; `App.merge.openDialog`, `App.merge.closeDialog()`, `App.merge.isDialogOpen()`; `App.merge.hasHistory(type, index)`, `App.merge.describeUnmerge(type, index)` → `{ok, errors, survivorName, originals, edited, stopCount}`, `App.merge.unmerge(type, index)` (sync, one undo step), `App.merge.openUnmergeDialog(type, index)`. `primary` is an index, or a ref for `linemix`.
- `run` order: analyze → prepare → cancel/fingerprint check → ONE `App.undo.push()` (after routing) → apply → repoint stops → splice others out directly (**never `App.removeX` in a loop** — each pushes its own undo) → re-render → `App.onFeatureDelete()` → re-select survivor.
- Survivor: the primary in place, except line + route with a route primary — the first selected line survives and takes the route's name, `properties.color`, `APPEARANCE_KEYS` overrides and merged attributes. Line + route always yields a Line. Points keep the primary's location then call `App.dropPointWalksheds` / `App.ensurePointWalksheds` / `App.refreshBuffers`. Polygons union via `App.foldAnalysisUnion`; a MultiPolygon result blocks, holes dropped. Stop `associatedRoutes` refs to removed features are repointed to the survivor and de-duplicated. Reversed directional segments warn.
- **Unmerge history:** `commit()` deep-clones every selected feature BEFORE `apply` and stamps `properties._mergedFrom = {version: 1, at, survivorRef, originals: [{type, feature}], stops: [{pointId, before, after}], resultFingerprint}`. Clones keep their own `_mergedFrom` (Unmerge goes back one level); the survivor's clone is taken before the new record (no self-reference). `unmerge` restores the survivor in place, appends the others with original IDs (+ `App.ensureFeatureIds()`), reverses stop links (exact if unchanged since, else best effort); a fingerprint mismatch shows an amber warning.
- Dialogs (`.fm-*`) list `App.describeFeatureUsage` results; focus trapped, global shortcuts suppressed. `App.merge._dialogKit` (for split.js): `el`, `renderList`, `buildShell(title)`, `buildActions(box, okLabel)`, `installDialog(overlay, box, onEnter?)`, `renderUsage(container, {warn, info}, heading?)`, `closeDialog()`, `isOpen()`, `isCurrent(dlg)` — one dialog at a time across merge, unmerge and split.

## split.js
Loads right after `merge.js`. See docs/archive/feature-split-plan.md; smoke test `test/feature-split-smoke.mjs`.
- A **cut** is `{segIndex, t}` or a click location; `App.split.resolveCut(coords, lngLat, hintSeg?)` takes the nearest point, snapped to a vertex within ~10 px (`App.map.project`; ~25 ft without a map).
- Pure, golden-tested (`test/cases/split.mjs`) on `App.splitGeom`: `cutAt`, `locate`, `snapToVertex`, `partitionWaypoints`, `splitRunTime`, `assignStops`, `isLoop`, `uniqueName`, `lengthMi`, `App.splitGeom.sectionBetween(coords, cutA, cutB)`, `joinPieces(a, b)`, `cutSection(coords, waypoints|null, cuts, loop)` → `{pieces, waypoints, sectionPiece}`, `waypointCut(coords, waypoints, k)`, `App.splitGeom.matchOppositeCuts(oppCoords, cutPoints, maxFt, endGuardFt)` → `{ok, reason: ""|"far"|"end"|"close", cuts, worstFt}`, `App.splitGeom.pairPieces(ourPieces, oppPieces)`, `midpointOf(coords)`.
- `App.split.analyze(type, index, cuts)` → plan (sync, never mutates): `{ok, errors, warnings, summary, type, index, featureId, name, cuts, pieces: [{coords, waypoints, lengthMi, name, runTime}], stops, stopsMoved, stopsBoth, serviceId, newServiceIds, hasHistory, sectionPiece?, usage: {warn, info}, opposite?, pairWarning?}`. Refuses non-line/route, a cut within ~30 ft of an end or another cut, and a single cut on a loop (ends within ~50 ft).
- `App.split.run(type, index, cuts, choices)` or `run(plan, choices)` → `{ok, type, indices, ids, message, opposite?} | {ok:false, errors}`; `choices = {names, service: "new"(default)|"none"|"same", opposite, oppositeNames}`. One `App.undo.push()`. First piece keeps the slot, ID, `colorSeq`, `seq`, name; others get `App.nextFeatureId`, unique `"<name> (2)"`, copied attributes/overrides, explicit color or a fresh `colorSeq`, `runTime` split by length; `_mergedFrom` removed from all. Stops re-link to the nearest piece (both within ~50 ft of a cut).
- `App.split.openDialog(type, index, where)`, `App.split.closeDialog()`, `App.split.isDialogOpen()`, `App.split.canSplitAt(type, index, lngLat)` (Split here offered: line/route, not loop, not near an end).
- **Split out section** (two cuts → 3 pieces; a point within ~30 ft of an end drops that cut). `run` selects only `plan.sectionPiece`. On a loop the rest stays ONE piece keeping the feature (now starting at the second cut), pieces `[rest, section]`; a cut near the loop join is refused. Pick mode: `App.split.startSectionPick(type, index, where)` sets `App.drawMode = "split-pick"` with preview layers `split-preview-line`/`split-preview-cut` on source `split-preview`; `cancelPick()`, `isPicking()`; app.js shortcuts ignore keys during `split-pick`.
- **Split at this node** (vertex-edit menu): `App.split.nodeCut(type, index, vertexIdx)` → cut | null, `App.split.splitAtNode(type, index, vertexIdx)`.
- **Opposite direction:** for one half of a paired Service (exactly one other pattern, opposite direction, neither a loop) `plan.opposite = {available, reason, type, index, featureId, name, direction, plan, pairOf}`; unavailable when a point is > `OPP_MAX_FT` (300 ft) from the mate, within 30 ft of its end, or matched cuts are within 30 ft. With `opposite: true` both split in ONE undo step and each mate piece takes the serviceId of the piece it pairs with (`new`: `"<id> (2)"`… so every pair stays a valid 2-pattern Service).
- `undo.js restore()` exits edit mode when the selected/edited feature no longer exists (prevents orphan handles after undoing a split).
- Re-merging pieces reproduces the original exactly for a vertex cut; a mid-segment cut leaves one collinear vertex.

## attribute-summary.js (system module `"attribute-summary"`)
Registered `system: true` (hidden from the Analysis menu by the `entry.system === true` skip in `buildAnalysisButtonsHTML()`), `popupWidth: 1000`. Opened by `App.openAttributeSummary()` from `#open-attribute-summary` under Feature Settings. Body `projects/attribute-summary-popup.html`: one `<section data-section="…">` per type (point/line/route/polygon/textbox/label) with an `.as-table`, hidden while the type has no features.
- Attribute data only; every row's swatch opens the Appearance popover (no extra column). Inputs bind directly to `feature.properties` / `.attributes` — no parallel state; each edit calls `App.cache.save()` and `App.refreshFeaturePanel()` (markers also `App.updateLabelAppearance(idx)` / `App.updateTextBoxAppearance(idx)`). Does NOT register with `App.cache.registerModule`.
- `update(core)` re-renders, guarded by `App.popup.isOpen() && App.popup.currentModuleId() === "attribute-summary"`.
- Columns: Lines/Routes share `.as-grid-routelike` (swatch · name · direction · mode · service · avg speed · run time · bands · Net · Buffer · copy); Routes show a muted `—` in Net to keep the shared grid aligned. Points `.as-grid-points` (… stop ID · routes badge · Buffer · copy). Buffer (`.as-col-buffer`, 116 px) calls `App.buildBufferRadiusControl`. Polygons: swatch · name · notes · copy. Text Boxes/Labels: name · size · background · text swatch (no copy).
- **Copy Attributes** (`#asCopyModal`): `COPY_FIELD_DEFS` (`kind: "text"|"select"|"number"|"bands"|"routearray"`). Point: `group`, `serviceAreaType`, `_bufferRadius`, `stopId`, `associatedRoutes`. Line/Route (`COPY_FIELDS_ROUTELIKE`, one shared pool): `group`, `direction`, `mode`, `avgSpeed`, `runTime`, `service`, `networkRole`, `_bufferRadius`. Polygon: `group`, `notes`. `target: "properties"` (only `_bufferRadius`) reads/writes `feature.properties`; an explicit 0 radius copies, an absent one doesn't. **`serviceId` is never copyable** — it would silently merge Services. Blank source fields never overwrite targets. `applyCopyAttributes` takes one `App.undo.push()`, replicates `serviceAreaType` side effects (`App.ensurePointWalksheds()` / `App.refreshBuffers()` / `App.notifyProject()`) and calls `App.rebuildBuffersForType(type)` per touched type after a `_bufferRadius` copy. `closeCopyModal()` runs on `onClose`.
