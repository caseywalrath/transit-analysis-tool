# Drawing and features

Reference detail moved verbatim from `CLAUDE.md`. Read the code when this and the code disagree.

## Files

- **`points.js`** — Points, user-defined buffers (default 0.5 mi), union polygon, point drag support

- **`lines.js`** — Line drawing (polylines with snap-to-close), line buffers (default 0.5 mi), rubber-band preview, vertex editing

- **`routes.js`** — Route drawing (OSRM street-snapped), route buffers (default 0.5 mi), throttled snapped preview, waypoint-only vertex editing

- **`polygons.js`** — Polygon drawing (vertex-by-vertex with snap-to-close), rubber-band preview, vertex editing

- **`editing.js`** — Feature editing: point click-drag, line/polygon/route vertex editing with orange handles **Map right-click feature menu** (single-selects, except: right-clicking a member of a 2+ selection keeps the selection and shows the group menu from `App.bulkFeatures.groupMenuItems`, with Merge… when mergeable; the handler also runs while `App.drawMode === "box-select"`): Attributes, Duplicate, **Unmerge…** (only when the feature carries `properties._mergedFrom` — `App.merge.hasHistory`), Hide/Show, Delete; it opens `App.merge.openUnmergeDialog`.

- **`features.js`** — Right-side feature panel: lists features, editable names, per-item type icons (tinted with the feature's resolved color; clicking one opens the shared Appearance popover — see `feature-appearance.js`), gear icon (⚙) per row to open the floating attributes popup, right-click context menu with Attributes option (and, for a multi-selection of 2+ lines or 2+ polygons, **Merge…** via `App.merge` — see the `merge.js` entry; the right-clicked row becomes the default survivor). Row click selects/highlights feature on map only. Delete (trash icon) stays in the row with an inline confirm strip. The main Features list is sortable (Name/Type/Date added/Group, ascending/descending, show/hide groups) via a sort icon button in the panel header (`#fp-sort-btn`) or right-click on the header — display-only, never reorders `App.points`/`lines`/`routes`/`polygons` or map draw order; the Labels and Text section is unaffected and always sorts by name. Exports refreshFeaturePanel, openColorPicker, updateFeatureColor. A 2+ selection's right-click menu adds the `App.bulkFeatures` items (Zoom to selection, Merge…, Hide N, Delete N features…) before Group…/Ungroup. The single-selection right-click menu also offers **Unmerge…** (just before Hide/Show) for a feature with `properties._mergedFrom`; it is never offered on a multi-selection.

- **`box-select.js`** — Box select (`docs/box-select-plan.md`; Phases 1-4). **Phase 4:** Shift+drag on the map starts a box with the tool off (no other draw mode active); it replaces (Ctrl/Cmd still removes), the click after it is swallowed, and MapLibre's own Shift+drag box zoom is disabled (`boxZoom: false` in `map.js`). **Phase 3 group actions:** `App.bulkFeatures` (bottom of the file; `usable`, `describe`, `anyVisible`, `setHidden`, `remove`, `confirmRemove` (a `.fm-*` dialog, one undo step), `zoomTo`, `groupMenuItems(list, mergeItem)` -> Zoom to selection, optional Merge…, Hide/Show N, Delete N features…) is shared by the map right-click menu (`editing.js`), the Features-pane menu (`features.js`) and the Delete key (`app.js`); labels are ignored. Loads right after `selection.js`. (1) Pure screen-pixel hit-test helpers on `App.boxSelectGeom` (no DOM/map/turf, golden-tested in `test/cases/box-select.mjs`): `normRect`, `pointInRect`, `segmentIntersectsRect` (Liang-Barsky), `pointInRing` (even-odd), `bboxOf`, `bboxIntersectsRect`, `lineHits(pts, rect, mode)`, `polygonHits(rings, rect, mode)` with `mode` `"touch"` or `"within"`. (2) The drag tool, active while `App.drawMode === "box-select"` (toolbar dashed-box button right of Measure, or the `A` key; entering it does NOT clear the selection). Mouse events are intercepted on `window` in the capture phase while the tool is on, so MapLibre never receives the mousedown/click/dblclick — the map does not pan and there is no `dragPan` state to restore; wheel zoom still works and right-click falls through. On mousedown every visible point/line/route/polygon (hidden skipped, Multi* geometries handled) is projected to pixels once; a dashed `.box-select-rect` and a live count `.box-select-badge` (rAF-throttled) follow the mouse inside the map container. On release: plain = replace, Shift = add, Ctrl/Cmd = remove, Alt = fully inside (else touches), applied via `App.setSelection`; a drag under 4 px acts as a click (topmost feature under the cursor, points first; an empty plain click clears). The tool stays on; Escape cancels a drag in progress, else exits the tool. `App.boxSelect = { isActive, isDragging, cancel }`. Browser smoke test: `test/box-select-smoke.mjs`.

- **`feature-appearance.js`** — Shared per-feature **Appearance** editing (`docs/feature-appearance-plan.md` Phase 1). Loads after `features.js`, before `feature-attributes.js`/`layers-panel.js`. Two exports: (1) `App.openAppearancePopup(anchorEl, type, index, opts)` — the singleton popover `#fp-appearance-popover` (z-index 9150, `.fa-*` styles): an inline Color row (swatch grid + hex entry, built by `App.buildColorPickerBody` from `features.js`; a × shows once `properties.color` is set), then Opacity / Weight (Size for points, Width for polygons) / Offset and **Line style** (lines + routes only) rows, then **Reset all** (clears color, opacity, width, a manual offset and the line style in ONE undo snapshot via `App.undo.batch`). **Line style** (`docs/feature-appearance-plan.md` Phase 3 UI; `buildLineStyleRow`) is a Solid | Dashed | Dotted segmented control (`.fa-segmented`/`.fa-seg-btn`, active = `--accent-soft`/`--accent`; muted when Solid) with the usual × (shown only when non-solid). It is part of `App.buildFeatureOverrideRows`, so the Layers-tab per-feature drawer gets it too; it never appears for points/polygons. It reads `App.normalizeLineStyle(properties._lineStyle)` and writes ONLY through `App.setFeatureLineStyle` (one undo step per click, which also re-renders, saves and refreshes panels) — do not set `_lineStyle` directly from UI code. No Buffer row — buffer radius is study-area geometry, not appearance (it lives in the Attributes popup's Study area section, see `feature-attributes.js`). Opened from four surfaces: the Features-pane type icon (`features.js`), the Attributes popup header swatch (`feature-attributes.js`), the Layers-tab feature-row swatch (`layers-panel.js`) and the Attribute Summary swatch (`attribute-summary.js`); labels and text boxes have no appearance cascade and keep the plain `App.openColorPicker`. `opts.onChange()` lets the caller refresh its own swatch. Re-opening on the same feature toggles it closed (also when the click follows the outside-mousedown that already closed it — keyed by feature, because panel refreshes rebuild the swatch element); Escape and outside mousedown close it. `App.closeAppearancePopup()`, `App.isAppearancePopupOpen()`. (2) `App.buildFeatureOverrideRows(type, feature, {onChange})` → array of DOM rows — **the single implementation of the "muted default until overridden, × clears" cascade rows**; the popover and the Layers-tab per-feature drawer both call it (the drawer passes `includeBuffer: true` until Phase 2). Semantics are the original drawer's: polygon opacity writes `_fillOpacity`+`_borderOpacity` via `App._polyOpacityValues`, offset writes `_offset`+`_offsetManual` and its × re-runs `App.computeOverlapOffsets()` when `#offsetOverlap` is checked. **Features are held as stable `{type, id}` refs and resolved on every read/write** (`App.featureById`), so an undo/redo (which replaces the feature objects), merge or delete while the popover is open can never write to a stale object; the popover closes if its feature is gone, and rebuilds itself after Ctrl/Cmd+Z/Y. **Undo = one snapshot per gesture** (a scrub drag, one +/− click, one typed value, one ×, one color pick): each row arms a flag on mousedown/click/change (capture phase) and the first value commit after it takes the snapshot — this also gives the Layers drawer undo, which it did not have before. Browser smoke test: `test/feature-appearance-smoke.mjs`.

- **`feature-attributes.js`** — Floating draggable attribute popup (singleton, #fp-attr-popup): ATTR_FIELDS config per type, openAttrPopup(featureType, featureIndex, feature), closeAttrPopup(), isAttrPopupOpen(), getAttrPopupFeature(). Popup is 320px wide, position: fixed, docked left (24px / 60px) on a fresh open, draggable by title bar, clamped within viewport, and collapsible to its title bar. Its header swatch (left-aligned row below the title) opens the shared Appearance popover (`feature-appearance.js`) — the old opacity/buffer/width/offset/reset icon strip was removed; it closes on Escape or X button. Points/Lines/Routes have a **Study area** section whose Buffer control (`App.buildBufferRadiusControl`, writes `properties._bufferRadius`) is shared with the Attribute Summary Buffer column — see the `### feature-attributes.js` API section. Auto-updates when a different feature is selected while open. Attributes stored in feature.properties.attributes (lazy-init). Route/line fields: group (universal grouping key with autocomplete datalist), direction (Both/NB/SB/EB/WB/Inbound/Outbound/Loop/CW/CCW), mode, serviceId (Route Costing pairing key — route+line-only datalist via buildServicePicker; replaces the deprecated routeId field), avgSpeed (default 14 mph, seeded on lazy-init), service bands per day (weekday/saturday/sunday), notes. Polygon fields: group, notes. Point fields: group, serviceAreaType (`""`/circular buffer vs `"walkshed"` — drives the Walkshed study-area substitution in `points.js rebuildBuffers()`; changing it fires `App.ensurePointWalksheds()` + `App.refreshBuffers()` + `App.notifyProject()`), stopId, associatedRoutes. **Any change to this attribute schema must be mirrored in `js/projects/attribute-summary.js` and the `.as-grid-*` column templates in `css/style.css` — see "Common Issues to Prevent" above.** `buildSelect` supports an optional `field.optionLabels` map (value→display text) and a `field.onChange(attrs)` hook. **Field sections (`docs/network-connectors-plan.md` Phase 2):** a field may carry an optional `section: "<label>"` string; the renderer emits a small `.fp-attr-section` header row before the first field of a new section value, and fields with no `section` render exactly as before (this is why `label`/`textbox`/`polygon` are untouched). `TRANSIT_FIELDS` (tagged `section: "Transit service"`) is the shared source of the route/line transit fields: `ROUTE_FIELDS` = `TRANSIT_FIELDS` + the Study area `bufferRadius` field; `LINE_FIELDS` = `TRANSIT_FIELDS` + one Lines-only field, `networkRole` (`""`/`"connector"`, section `"Walk network"`, `onChange: onNetworkRoleChange` — a Phase 2 stub that calls `App.refreshNetworkConnectors()` behind a `typeof` guard; Phase 4 gives it real effect). Routes don't get this field — a Route already follows an existing street, so "connect this to the walk network" doesn't apply. A Line row in the Feature panel carrying `attributes.networkRole === "connector"` also gets a small muted `.fp-net-chip` ("walk") next to its name (`js/core/features.js`), so connectors are distinguishable from transit Lines at a glance.

- **`merge.js`** — Feature Merge (`docs/feature-merge-plan.md`, Phases 2-3: lines, polygons, routes, points, line + route; Phase 4a: Unmerge). Loads after `feature-attributes.js`. Three layers: (1) **pure helpers**, no turf/DOM, loadable by the golden harness — `App.mergeGeom.chainLines` (orders N polylines end to end: every segment × orientation tried as the start, greedy nearest-endpoint append, smallest total connector wins; a join under ~1 m drops the duplicate vertex), `App.mergeGeom.findBranch` (Y/T junction detector, ~50 ft tolerance — an endpoint near another line's own end is an ordinary join), `App.mergeGeom.lengthMi`, `App.mergeGeom.planRouteChain`/`assembleChain`/`routeChain` (route ordering + waypoint concatenation — waypoints reversed with their segment, a duplicate waypoint dropped at a coincident join — and assembly of routed connector geometry between the segment ends), and `App.mergeAttrs` (`hasValue`, `fieldHasValue(kind, v)` — the has-a-value semantics Attribute Summary's Copy Attributes now delegates to —, `mergeAttributes(items, primaryPos, {kind})`: "primary wins, fill blanks", `notes` joined, line `runTime` summed / `avgSpeed` length-weighted when every feature has one, discarded-value list, Service/direction warnings; for `kind:"point"` `associatedRoutes` is a union de-duplicated by featureType+featureId, conflicting `stopId`s warn, and `serviceAreaType` is primary-only because a blank value is the real "circular buffer" choice; and `reversalWarnings(items, chain)` — one warning per reversed segment whose `direction` is NB/SB/EB/WB/Inbound/Outbound/CW/CCW); (2) a per-type `STRATEGIES` table (`line`, `route`, `point`, `polygon`, `linemix` = line + route) whose `analyze()` is synchronous and cheap and returns a plan `{ok, errors, warnings, summary, discarded, survivor, removed, removedIds, stopsRepointed, apply, repoint, prepare?}`; `prepare(ctx)` is the optional async step (routes only: street-routes each non-touching connector via `App.fetchRouteGeometry`, sequentially, falling back to a straight connector per failure) and runs only when the user clicks Merge; (3) `App.merge` — `mergeableSelection(selected)`, `analyze()`, `run()` and `openDialog()`. Selection members are `{type, index}` refs (indices are per type; single-type callers may pass plain numbers, `linemix` takes refs). `run(type, indices, primary, {isCancelled, onProgress})` returns a **Promise**: analyze → `prepare` (if any) → cancel/fingerprint check → ONE `App.undo.push()` (taken only after routing finishes) → `apply` → repoint stops → splice the others out directly (never `App.removeX` in a loop — each pushes its own undo snapshot) → re-render every touched type → `App.onFeatureDelete()` housekeeping → re-select the survivor at its recomputed index. The primary survives in place, except line + route with a route primary: the first selected **line** survives and takes the route's name, `properties.color` and appearance overrides (`APPEARANCE_KEYS` in merge.js: `_opacity`, `_lineWidth`, `_offset`, `_bufferRadius`, `_lineStyle`, …) and the merged attributes. Line + route always yields a Line (snapped geometry kept exactly, straight connectors, `waypoints` = vertex count). Points keep the primary's location and then call `App.dropPointWalksheds` / `App.ensurePointWalksheds` / `App.refreshBuffers`. Polygons are unioned with `App.foldAnalysisUnion`; a MultiPolygon result blocks the merge and holes are dropped. The dialog is an app-level modal (`.fm-*` styles in `css/style.css`): primary radio list, result summary, "Will be discarded", amber warnings, red blocking errors (Merge disabled), a "Routing connections…" line while routes are being routed (Merge + radios disabled, Cancel/Escape still abort with nothing changed), focus trapped, global shortcuts suppressed while open. **Unmerge (Phase 4a):** `commit()` deep-clones every selected feature BEFORE `plan.apply()` mutates anything and stamps `properties._mergedFrom = { version: 1, at (ISO), survivorRef: {type, id}, originals: [{type, feature}], stops: [{pointId, before, after}], resultFingerprint }` on the survivor. A clone keeps whatever `_mergedFrom` its feature already had (so Unmerge goes back exactly one level); the survivor's own pre-merge clone is taken before the new record is set, so nothing is self-referencing. `stops` holds the full pre- and post-merge `associatedRoutes` of every point the merge changed (keyed by `pointIdx`); `resultFingerprint` is a stable string of name + color + geometry + waypoints + attributes right after the merge. `App.merge.unmerge(type, index)` (one undo snapshot) replaces the survivor in place with the clone of its own original, appends the other originals to the ends of their type arrays with their original IDs (plus `App.ensureFeatureIds()` as a safety net), reverses stop links (exact when the stop still has the post-merge links — compared by type + ID; best effort if edited since), then re-renders every touched type and runs the merge housekeeping. The Unmerge confirm dialog reuses the `.fm-*` shell (`buildShell`/`buildActions`/`installDialog`, shared with the merge dialog) and shows an amber warning when the fingerprint no longer matches. Pure helpers, golden-tested in `test/cases/merge.mjs`: `App.mergeHistory.{stableStringify, fingerprintFeature, stopChanges, restoreStopRefs, validateHistory, stripHistory}`. The Merge dialog also lists `App.describeFeatureUsage` results for every selected feature (survivor: "now refers to the whole merged feature"; removed: "this reference will be missing") via the shared `renderUsage` (exported on `_dialogKit`).

- **`split.js`** — Feature Split (`docs/feature-split-plan.md` Phase 1: **Split here** for lines and routes). Loads right after `merge.js` and reuses its `.fm-*` dialog shell via `App.merge._dialogKit`. Pure helpers on `App.splitGeom` (no turf/DOM/map, golden-tested in `test/cases/split.mjs`): `cutAt`, `locate`, `snapToVertex`, `partitionWaypoints`, `splitRunTime`, `assignStops`, `isLoop`, `uniqueName`, `lengthMi`. Engine `App.split.analyze/run/openDialog`. The first piece keeps the feature (array slot, ID, `colorSeq`, `seq`, name); other pieces are appended with `App.nextFeatureId`, names `"<name> (2)"` (unique), copied attributes/appearance overrides, explicit color copied or a fresh `colorSeq` when Automatic, `runTime` split by length, new/none/same Service choice, `_mergedFrom` removed from every piece; stops re-link to the nearest piece (both pieces within ~50 ft of a cut). One undo snapshot. Map right-click **Split here** (after Duplicate) in `editing.js`, hidden on loops and within ~30 ft of an end. **Phase 2:** map right-click **Split out section…** (after Split here; every line/route, the only split offered on a loop) starts a two-point pick mode (`App.split.startSectionPick`: `App.drawMode = "split-pick"`, crosshair, rAF-throttled preview layers `split-preview-line`/`split-preview-cut` on source `split-preview` above all drawn features; click = second point -> dialog, Escape / right-click / a toolbar tool button cancels and removes the layers; `app.js` shortcut listeners ignore keys while `split-pick` is active), and the vertex-edit menu (`showVertexCtxMenu`) gains **Split at this node** (interior line vertex / interior route waypoint, hidden on ends and loops; leaves vertex-edit mode before the dialog). Browser smoke test: `test/feature-split-smoke.mjs`. **Phase 3 (module awareness):** the Split dialog lists `App.describeFeatureUsage` results (amber = warn, muted "Also used by" = info, worded "after the split this refers to part 1 only"), and for one half of a paired Service (the `serviceId` has exactly one other pattern, with the opposite direction, neither a loop) offers **Also split the opposite direction at the matching point** (default off) — see the `### split.js` API section.

- **`service-assembly.js`** — Shared transit-Service assembly for Route Costing and Trip Builder: `App.buildTransitServices`, `getEffectiveServiceBands`, `directionSummary`, `hasBlockingWarnings`, `migrateServiceKey`. Service keys: paired `"service-<serviceId>"`; solo `"solo-<type>-id<stable ID>"` (e.g. `"solo-route-id12"`) — ID-based so they survive delete/merge of earlier features. The legacy `"solo-<type>-<arrayIndex>"` form is recognizable (no `id` infix) and `migrateServiceKey(key, arraysByType?)` upgrades it (valid only inside a module `apply()` hook — see "Module references by stable ID"). Each pattern carries `featureId` (stable) alongside the assembly-time `featureIndex`.

- **`attribute-summary.js`** — Attribute Summary "system" module: registered with `system: true` so it does NOT appear in the Analysis dropdown. Opened via the Attribute Summary… button under Feature Settings (right-side feature panel). Single-column popup with one section per feature type (Points / Lines / Routes / Polygons / Text Boxes / Labels). Each row binds inputs directly to `feature.properties` and `feature.properties.attributes` — no duplicated state. Attribute data only — appearance (opacity/width/buffer/offset) is edited from the Layers tab (`js/core/layers-panel.js`) or the shared Appearance popover (`js/core/feature-appearance.js`), which every row's color swatch opens; the swatch adds no column and no duplicate editor, so the two-surface rule is unaffected. Time bands and route-pickers are rendered as compact pill badges (`fp-bands-badge`, `fp-route-badge`) that open a shared mini-popup (`#fp-mini-popup`) with the same UI as the per-feature attribute popup.

- **`attribute-summary-popup.html`** — Attribute Summary popup body: single column, one `<section data-section="…">` per feature type (point/line/route/polygon/textbox/label) with an inner `.as-table` populated by JS. All sections are hidden by default and revealed only when that feature type has any features.

## API

### API — points.js
`points` (Point array), `buffers` (Polygon array), `addPoint(lon, lat)`, `addPointWithOpts(lon, lat, opts)`, `rebuildBuffers(radiusMiles)`, `refreshBuffers()` (rebuild at the current radius — used by the Walkshed module), `movePoint(index, lng, lat)`, `removePoint(index)`, `clearPoints()`, `undoLastPoint()`, `duplicatePoint(index)`, `renderPointLayers()`, `bufferUnionPolygon()`, `getUnion()` (alias), `bboxStringFromFeature(feat)`

`rebuildBuffers()` substitutes a cached walkshed polygon for the circle when a point has `attributes.serviceAreaType === "walkshed"` and `App.getPointWalkshed(pointIdx)` returns one (else it falls back to the circular buffer). The resulting `buffers[i]` carries `properties.walkshed = true`.

### API — lines.js
`lines` (LineString array), `lineBuffers` (Polygon array), `handleLineClick(lngLat)`, `rebuildLineBuffers(radiusMiles)`, `lineBufferUnionPolygon()`, `removeLine(index)`, `clearLines()`, `undoLastLine()`, `cancelLineDrawing()`, `renderLineLayers()`, `setLinePreview(lngLat)`, `updateLineVertex(lineIndex, vertexIndex, lng, lat)`, `duplicateLine(index)` (copies color + every appearance override via `App.copyAppearanceOverrides`, never `_mergedFrom`)

Saved lines render in three style layers on the `lines` source — `lines-layer` (solid), `lines-layer-dashed` (`line-dasharray [4, 2.5]`), `lines-layer-dotted` (`[0, 2]` + `line-cap: round`), filtered on `properties._lineStyle` (see the `utils.js` line-style helpers below). `App.applyFeatureOpacity`/`applyLineWidth` paint all three; `line-offset` is set on all three at creation.

### API — routes.js
`routes` (LineString array with `waypoints` property), `routeBuffers` (Polygon array), `handleRouteClick(lngLat)`, `setRoutePreview(lngLat)`, `rebuildRouteBuffers(radiusMiles)`, `routeBufferUnionPolygon()`, `removeRoute(index)`, `clearRoutes()`, `undoLastRoute()`, `cancelRouteDrawing()`, `renderRouteLayers()`, `updateRouteWaypoint(routeIndex, waypointIndex, lng, lat)`, `duplicateRoute(index)` (copies every appearance override, like `duplicateLine`), `fetchRouteGeometry(waypoints)` → `Promise<coords | null>` — the same router drawing/editing uses (local road network first via `App.findLocalRoute` when loaded, then the OSRM servers; `null` = unavailable, caller draws a straight line; on total failure it also posts the "using straight line" status). Used by Feature Merge to street-route route connectors.

Saved routes render in `routes-layer` / `routes-layer-dashed` / `routes-layer-dotted`, exactly like lines (per-feature `_lineStyle`).

Route features store `properties.waypoints` (user click points) separately from the full street-snapped `geometry.coordinates`. Vertex editing shows handles on waypoints only. OSRM demo server used for routing (`https://router.project-osrm.org/route/v1/driving/`). Preview is throttled: straight line immediately, street-snapped after ~1s of mouse idle (AbortController used to cancel stale fetches).

### API — polygons.js
`polygons` (Polygon array), `handlePolygonClick(lngLat)`, `removePolygon(index)`, `clearPolygons()`, `undoLastPolygon()`, `cancelPolygonDrawing()`, `renderPolygonLayers()`, `setPolygonPreview(lngLat)`, `updatePolygonVertex(polyIndex, vertexIndex, lng, lat)`

### API — editing.js
`_editing` (edit state or null), `exitEditMode()`, `_initEditing()` (called from app.js on map load). Every hover/click/right-click/vertex-edit hit test queries `App.lineStyleLayerIds()` and classifies hits with `App.lineStyleLayerType(layerId)`, so dashed/dotted lines and routes are selectable, editable and draggable exactly like solid ones. Drag previews copy all feature properties (including `_lineStyle`), so a dashed line stays dashed mid-drag.

### API — features.js
`refreshFeaturePanel()`, `rerenderForType(type)`, `getTypeDefaultColor(type)`, `showContextMenu(x, y, options)` (closes on the next mouse press outside it or Escape — listeners attach immediately, not after a timer; `App.closeContextMenu()` closes it programmatically; items may carry an optional additive `onHover(isEntering)` — true on mouseenter/focus, false on mouseleave/blur and also when the menu closes by any path (item click, outside click, replaced by another menu) while an item is hovered; plain `{label, action}` callers unaffected), `openColorPicker(anchorEl, color, onChange)`, `buildColorPickerBody(currentColor, onPick)` (the picker body as a standalone element — embedded inline by the Appearance popover; `openColorPicker` wraps the same body in its floating picker, so a change here changes every picker at once; `docs/color-picker-variety-plan.md`. Contents: a 10-hue x 5-row grid of 50 swatches (`PICKER_COLORS` — red, orange, yellow, green, teal, cyan, blue, indigo, purple, pink in four shades light to dark, then a neutral row white to black ending in a warm tan and brown; swatch hex values are data, exempt from the design-token rule; classes `.fp-cp-cell`, `.fp-cp-cell-selected` marks the current color), a **Recent** row of up to 10 swatches (`.fp-cp-recent-cell`, hidden while empty) and a hex entry + **Custom…** button wrapping a hidden `<input type=color>` (`.fp-cp-custom-input`; only its `change` event commits, `input` is ignored, so one choice is one `onPick` and one undo step). Every pick path (grid, Recent, hex, Custom) funnels through one internal `pick()` that records the color in the Recent list before calling `onPick`. **Recent** is a per-browser convenience, NOT session state (not in `cache.js`): a newest-first, de-duplicated, max-10 list of lowercase `#rrggbb` in `localStorage` key `mat-recent-colors` (every read/write in try/catch), seeded the first time from the colors in use on the map via `App.resolveFeatureColor` over `App.collectDrawnFeatures()`. The body exposes `setColor(c)` (seeds the hex field, the Custom input and the selected-swatch mark) and `refreshRecent()`; `openColorPicker` calls both each time it opens. Browser test: `test/feature-appearance-smoke.mjs`), `collectDrawnFeatures()` (returns `[{ feature, type, index }]` across points/lines/routes/polygons — shared with the Layers panel), `UNIVERSAL_GROUP_KEY` (the `attributes.group` key string). The right panel header is a `Features | Layers` tab bar (panes `#fp-tab-features` / `#fp-tab-layers`); the tab toggle calls `App.refreshLayersPanel()` when Layers is shown.

### API — merge.js
`App.merge.mergeableSelection(selected)` → `{type, indices, primaryFor(featureType, featureIndex)}` | `null` (2+ selected: all one of `point`/`line`/`route`/`polygon`, or only lines + routes mixed → `type: "linemix"` with `{type,index}` refs as `indices`; anything else, including point + line, label, or line + route + point, is rejected), `App.merge.analyze(type, indices, primary)` → plan (synchronous; `plan.prepare` is the optional async routing step), `App.merge.run(type, indices, primary, opts)` → `Promise<{ok, survivorType, survivorIndex, removedIds, repoints, routing, message} | {ok:false, errors} | {ok:false, cancelled:true}>` (`opts.isCancelled()`/`opts.onProgress(i, n)`; `repoints` are the stop repoint records; the `_mergedFrom.stops` history is diffed separately from the points' before/after link lists), `App.merge.openDialog(type, indices, primary)`, `App.merge.closeDialog()`, `App.merge.isDialogOpen()`, and (Phase 4a) `App.merge.hasHistory(type, index)`, `App.merge.describeUnmerge(type, index)` → `{ok, errors, survivorName, originals: [{type, name, inPlace}], edited, stopCount}`, `App.merge.unmerge(type, index)` → `{ok, survivorType, survivorIndex, restored: [{type, index}], message} | {ok:false, errors}` (synchronous, one undo step), `App.merge.openUnmergeDialog(type, index)`. For single-type calls `primary` is a numeric index; for `linemix` it is a `{type,index}` ref. Pure, golden-tested: `App.mergeGeom.{chainLines, findBranch, lengthMi, routeChain}` and `App.mergeAttrs.{hasValue, fieldHasValue, mergeAttributes, reversalWarnings}` (`test/cases/merge.mjs`). The Merge… item exists only in the **Features panel** right-click menu (`features.js` `buildItem` contextmenu handler, next to Group…; the right-clicked row is the default primary, passed through `mergeSel.primaryFor`) — the map right-click menu always single-selects and the Layers panel rows are single-select, so neither offers it. A stop's `associatedRoutes[].featureId` refs to removed lines/routes are repointed to the survivor (featureType becomes the survivor's — `"line"` for line + route) and de-duplicated (Phase 1's unique IDs make this safe). When a reversed segment (line or route) has a directional `direction`, the dialog warns that its direction of travel is flipped in the result. Browser smoke test: `test/feature-merge-smoke.mjs` (Playwright; see its header; Phase 3 mocks the OSRM demo server at page level).

### API — split.js
Phase 1 of `docs/feature-split-plan.md`. A **cut** is `{segIndex, t}` (position on segment `segIndex`, `t` in 0..1) or a click location (`[lng, lat]` / `{lng, lat}`); a location is resolved with `App.split.resolveCut(coords, lngLat, hintSeg?)` — nearest point on the line, snapped to the segment's nearer vertex when within ~10 px on screen (`App.map.project`; ~25 ft without a map).

- `App.split.analyze(type, index, cuts)` → plan (synchronous, never mutates). `cuts` is an array (Phase 2 passes two for "Split out section…"); one bare cut is accepted. Plan: `{ ok, errors, warnings, summary, type, index, featureId, name, cuts (resolved, sorted), pieces: [{coords, waypoints, lengthMi, name, runTime}], stops: [{pointId, name, pieces}], stopsMoved, stopsBoth, serviceId, newServiceIds, hasHistory }`. Refuses non-line/route types, a cut within ~30 ft of an end or of another cut, and a single cut on a loop (ends within ~50 ft). Warns for a paired Service (opposite direction not split) and for merge history (Unmerge goes away).
- `App.split.run(type, index, cuts, choices)` or `App.split.run(plan, choices)` → `{ok, type, indices: [first, ...new], ids, message} | {ok:false, errors}`. Synchronous. `choices = { names: [per piece], service: "new" (default) | "none" | "same" }`. One `App.undo.push()`, mutates the first piece in place, appends the rest, re-links stops, re-renders, runs `App.onFeatureDelete()` housekeeping (notify + save), multi-selects the pieces.
- `App.split.openDialog(type, index, where)` — `where` is a click location or an array of cuts. Returns the plan shown. `App.split.closeDialog()`, `App.split.isDialogOpen()`.
- **Split out section (Phase 2).** `analyze`/`run`/`openDialog` with two cuts. Result is 3 pieces in line order; a point within ~30 ft of an end counts as that end (the cut is dropped, giving 2 pieces); both points at the two ends, or the same spot, or two points within ~30 ft of each other are refused. `plan.sectionPiece` is the index of the section piece and `run` selects ONLY that piece (a single cut still multi-selects all pieces). **Loops** (ends within ~50 ft): the section is the stretch between the two cuts in line order (the preview shows exactly that stretch, it never wraps through the start); the rest — the part before the first cut joined through the loop start to the part after the second — stays as ONE piece that keeps the feature (slot/ID/name) and now begins at the second cut; the section becomes the new feature (`"<name> (2)"`). Pieces are `[rest, section]`, `sectionPiece = 1`. A cut within ~30 ft of the loop's own start/end is refused (that point is the loop's join). Stops within ~50 ft of either cut link to both pieces.
- Pure helpers added for Phase 2 (golden-tested): `App.splitGeom.sectionBetween(coords, cutA, cutB)`, `joinPieces(a, b)` (drops a duplicate join vertex within ~1 m), `cutSection(coords, waypoints|null, cuts, loop)` -> `{pieces, waypoints, sectionPiece}`, `waypointCut(coords, waypoints, k)` (the geometry position of route waypoint k, placed exactly as `partitionWaypoints` does; a waypoint located at a cut is replaced by the cut point rather than kept as a near-duplicate).
- `App.split.startSectionPick(type, index, where)`, `cancelPick()`, `isPicking()`; `App.split.nodeCut(type, index, vertexIdx)` -> cut | null and `App.split.splitAtNode(type, index, vertexIdx)` (opens the dialog).
- `undo.js restore()` now exits edit mode when the selected / vertex-edited feature no longer exists after the restore (undoing a split that selected a new piece used to leave orphan edit handles).
- `App.split.canSplitAt(type, index, lngLat)` — whether the map menu offers Split here (line/route, not a loop, not near an end).
- **Phase 3 — opposite direction.** `analyze` adds `plan.usage = {warn, info}` (module references) and, for one half of a paired Service (exactly one other pattern with the same `serviceId` and the opposite direction — NB/SB, EB/WB, Inbound/Outbound, CW/CCW — and neither feature a loop), `plan.opposite = { available, reason, type, index, featureId, name, direction, plan (the mate's own split plan), pairOf }`. The mate's cut(s) are found by nearest position (`locate`) to each of our interior cut points (`App.splitGeom.matchOppositeCuts`); unavailable (checkbox disabled, reason shown) when a point is > 300 ft from the mate (`OPP_MAX_FT`), within 30 ft of its end, or two matched cuts are within 30 ft. `pairOf[j]` is the piece of ours that the mate's piece j runs alongside (`App.splitGeom.pairPieces`, nearest midpoint, each used once) — usually reversed. `run(plan, {opposite: true, oppositeNames})` splits both in ONE undo step; each mate piece takes the serviceId of the piece of ours it pairs with under the same Service choice (`new`: our part 1's partner keeps the original id, the others share `"<id> (2)"`, `"(3)"`…, so every pair is a valid 2-pattern Service — the mate's in-place piece may get the new id; `none`: partners of new pieces get `""`; `same`: all keep it). The result carries `opposite: {type, indices, ids}`. When the option is available, the "opposite direction has not been split" warning moves to `plan.pairWarning` (shown only while unchecked). Pure, golden-tested: `matchOppositeCuts(oppCoords, cutPoints, maxFt, endGuardFt)` → `{ok, reason: ""|"far"|"end"|"close", cuts, worstFt}`, `pairPieces(ourPieces, oppPieces)`, `midpointOf(coords)`.
- `App.merge._dialogKit` (exported by merge.js for split.js): `el`, `renderList`, `buildShell(title)`, `buildActions(box, okLabel)`, `installDialog(overlay, box, onEnter?)`, `renderUsage(container, {warn, info}, heading?)`, `closeDialog()`, `isOpen()`, `isCurrent(dlg)`. One dialog at a time across merge, unmerge and split.

Merging the pieces back with Merge… reproduces the original coordinates exactly when the cut was on a vertex; a mid-segment cut leaves one extra collinear vertex at the cut point (merge keeps it).

### API — feature-attributes.js
`openAttrPopup(featureType, featureIndex, feature)` — opens the floating attributes popup for the given feature. If the same feature is already shown, closes it (toggle). If a different feature was shown, replaces content in place (preserves dragged position). On first open, positions the popup at left: 320px, top: 60px (just right of sidebar, below toolbar).

`closeAttrPopup()` — hides the popup and clears current feature tracking.

`isAttrPopupOpen()` — returns boolean.

`getAttrPopupFeature()` — returns `{ featureType, featureIndex }` or null.

**Popup DOM:** `#fp-attr-popup` (position: fixed, z-index: 9000, width: 320px). Header (`.fp-attr-popup-header`) is draggable; drag state uses `initLeft/initTop` + mouse delta, clamped to keep ≥40px visible on all edges. Window resize re-clamps. Escape key closes. X button (`.fp-attr-popup-close`) closes. Body (`.fp-attr-popup-body`) contains Name row + type-specific field rows using existing `.fp-attr-row` / `.fp-attr-label` / `.fp-attr-input` classes.

**Auto-update on selection:** `selection.js selectFeature()` calls `openAttrPopup` if the popup is already open, so clicking a different feature row or map feature automatically switches the popup content.

**Feature attribute storage:** All feature types (routes, lines, points, polygons) can carry a `properties.attributes` object. Preserved automatically by session cache serialization. Lazy-init means old sessions without the field restore cleanly.

**Service pairing (Route Costing):** The `serviceId` field on route/line attributes is the dedicated pattern-grouping key consumed by the Route Costing module. Routes/lines sharing a `serviceId` string are grouped into one Service (1, 2 or 3+ patterns); standalone features become 1-pattern Services. The `direction` field (`Both`, `NB`, `SB`, `EB`, `WB`, `Inbound`, `Outbound`, `Loop`, `CW`, `CCW`) labels each pattern; Route Costing validates that 2-pattern Services use valid opposites (NB+SB, EB+WB, Inbound+Outbound, CW+CCW); in a 3+-pattern Service every pattern must instead have a one-way direction (anything but `Both`, which is also what a blank direction reads as). The Service field has its own route+line-only autocomplete datalist (`fp-service-datalist`) and inherits color across paired patterns. `serviceId` replaced the previously-unused `routeId` field; old prose referenced an `attributes.group`-based pairing — `group` is now strictly a general-purpose universal grouping field with no Route Costing semantics. `computePerRouteCDI`, `matchRoutesToCSV`, and the RF corridor dropdown still treat each feature as its own route — Service-aware logic is only implemented by Route Costing so far.

**Study area / buffer radius (`docs/feature-appearance-plan.md` Phase 2):** Points, Lines and Routes carry a "Study area" section (points: `serviceAreaType` then `bufferRadius`; lines/routes: a trailing `bufferRadius`; the point field order is now Stop ID, Routes, then Study area). The `bufferRadius` field (`type: "buffer-radius"`) is rendered by **`App.buildBufferRadiusControl(type, feature, {note})`** — the single implementation shared with the Attribute Summary Buffer column (two-surface rule). It reads/writes **`feature.properties._bufferRadius`, never `attributes`**; shows the type default (`App.featureSettings.bufferRadius`/`lineBufferRadius`/`routeBufferRadius`) muted until overridden, with a × to clear. Buffers rebuild live on every scrub tick (`App.rebuildBuffersForType(type)`, exported), but the undo snapshot, `App.cache.save()` and `App.notifyProject()` (so analysis modules mark themselves stale) fire **once per gesture** — a typed value or +/- click is flushed on the next tick, a drag on mouseup. On a point with `serviceAreaType === "walkshed"` the control is disabled (note "Walkshed replaces the buffer"); `App.refreshBufferRadiusControls()` re-syncs live controls and is called from `onServiceAreaChange`. The control holds the feature as a stable `{type, id}` ref. `_bufferRadius` is also copyable via Attribute Summary's Copy Attributes (`target: "properties"` field def) and is no longer in the Layers per-feature drawer.

**Shared helpers (used by both the per-feature popup and the Attribute Summary module):**

`App.openTimeBandsPopup(feature, anchor, onChange)` — opens the Weekday / Saturday / Sunday time-bands editor for a route/line feature inside the shared `#fp-mini-popup` floating dialog. `anchor` is an optional DOM element used to position the popup. `onChange` fires when the popup closes (used by the badge button to refresh its label). The mounted UI is exactly the same `buildServiceSchedule(attrs)` widget used inline by the per-feature popup.

`App.openRoutePickerPopup(attrs, anchor, onChange)` — opens the route-picker checklist (point's `attributes.associatedRoutes`) inside `#fp-mini-popup`. Mutates `attrs.associatedRoutes` directly. Used by the Routes pill button.

`App.refreshAttrPopupSwatch()` — re-syncs the popup's header swatch with the shown feature's resolved color (called by the Appearance popover after a color change). The per-feature override icon strip and `App.buildOverrideIcons` were retired in favor of the shared Appearance popover (`feature-appearance.js`).

`App.buildPointRouteBadge(pointFeature)` — returns a small pill button (`.fp-route-badge`) showing the count of associated routes (e.g. `"3 routes"` or `"Add routes"`). Click opens `App.openRoutePickerPopup`. The per-feature point attribute popup also uses this badge in place of the previous inline checkbox grid (less vertical space, click-to-edit).

`App.buildTimeBandsBadge(feature)` — returns a small pill button (`.fp-bands-badge`) showing the per-day band count summary (e.g. `"3 · 1 · 0"` for Weekday · Saturday · Sunday) or `"Add bands"` if empty. Click opens `App.openTimeBandsPopup`. Used by the Attribute Summary module's Bands column.

`App.openMiniPopup(opts)` — generic opener for the shared `#fp-mini-popup` floating dialog. `opts` = `{ title, content (DOM node), anchor (DOM element), onClose (function) }`. Modules embedding their own attribute editors (e.g. Trip Builder's truncated Edit panel) call this rather than reimplementing the dialog shell. `App.closeMiniPopup()` closes whichever content is currently mounted.

`App.buildServiceScheduleEditor(feature)` — returns the Weekday / Saturday / Sunday time-bands editor DOM node (the same widget mounted by the per-feature popup and `App.openTimeBandsPopup`). Modules can append the returned node to their own container to embed the bands UI without duplicating it.

**Mini-popup (`#fp-mini-popup`):** singleton floating dialog used by the time-bands and route-picker badge buttons, and by Trip Builder's Edit panel. 320px wide, z-index 9100, draggable header, Escape to close, anchored beneath the trigger button when opened. Independent from `#fp-attr-popup` so the per-feature popup can stay open simultaneously.

### API — attribute-summary.js (system module, no public API)
Registered with `id: "attribute-summary"`, `system: true`, `popupWidth: 1000`. Opened via `App.openAttributeSummary()`, which is wired to the `#open-attribute-summary` button under the Feature Settings panel (right-side feature panel, below the "Offset overlapping Lines/Routes" toggle). Hidden from the toolbar Analysis menu by the `entry.system === true` skip in `buildAnalysisButtonsHTML()` (`js/app.js`).

**Layout:** single column. One `<section data-section="…">` per feature type (Points / Lines / Routes / Polygons / Text Boxes / Labels). Empty sections are hidden. The Lines and Routes tables share a column model: swatch · name · direction · mode · service · avg speed · run time · bands badge · **Net** · **Buffer** · **copy-attributes button**. Headers are short (`Avg Spd`, `RunT`, `Bands`, `Net`, `Buffer`) with `title=` tooltips for the full names; CSS Grid (`.as-grid-routelike`) keeps columns aligned. **Net** (`docs/network-connectors-plan.md` Phase 2) is the same `networkRole` field as the per-feature Attributes popup's "Walk network" field — a `""`/`"connector"` select for Lines, a muted `—` (`.as-cell-muted`) for Routes (Routes have no `networkRole`; the column exists so the shared grid template stays aligned between the two tables, per the two-surface rule below). **Buffer** (`docs/feature-appearance-plan.md` Phase 2; Points, Lines and Routes — `.as-col-buffer`, a 116px grid column in `.as-grid-points` (after Service) and `.as-grid-routelike` (after Net)) is the same per-feature buffer-radius control as the Attributes popup's Study area section — both surfaces call `App.buildBufferRadiusControl`, never their own editor; it is disabled on walkshed points. Points rows show: swatch · name · stop ID · `App.buildPointRouteBadge` · copy-attributes button. Polygons rows show: swatch · name · notes · copy-attributes button. Text Boxes / Labels rows show: name · size · background swatch · text swatch (no copy-attributes button — these are DOM markers, not analytical features; out of scope for Copy Attributes). Appearance (opacity/width/offset overrides) is not editable here — see the Layers tab (`js/core/layers-panel.js`); the module's own `COPY_FIELD_DEFS` likewise excludes every display property, since Copy Attributes only ever touched attribute data. `COPY_FIELDS_ROUTELIKE` (shared by the Line/Route copy pool) includes `networkRole` (`kind: "select"`) alongside `group`/`direction`/`mode`/`avgSpeed`/`runTime`/`service` — copying it onto a Route is harmless (Routes render no UI for it) but kept for schema symmetry with Lines.

**Field bindings:** Every cell input is wired directly to the live feature object — `feature.properties.name`, `feature.properties.attributes[key]`, `feature.properties.color`, `feature.properties.fontSize`, etc. There is no parallel state. After every edit the module calls `App.cache.save()` and `App.refreshFeaturePanel()`. For text/label markers it also calls `App.updateLabelAppearance(idx)` / `App.updateTextBoxAppearance(idx)` so the on-map marker re-renders.

**Live updates while open:** `update(core)` (called by `App.notifyProject()` after feature add/delete and after cache restore) re-renders the entire table list. DOM writes are guarded by `App.popup.isOpen() && App.popup.currentModuleId() === "attribute-summary"`.

**Internal functions:** `renderAll`, `renderPoints`, `renderLineLike` (shared between Lines and Routes), `renderPolygons`, `renderMarkers` (shared between Text Boxes and Labels), plus cell builders `buildSwatchCell`, `buildTextCell`, `buildNumberCell`, `buildSelectCell`, `buildColorSwatchCell`, and `buildServiceIdCell` (text input wired against the shared `fp-service-datalist` autocomplete).

**Copy Attributes (Points / Lines / Routes / Polygons):** a small `.fp-sib`-styled icon button (`buildCopyButton`) on each row opens `#asCopyModal` (a `.rf-weights-modal-overlay` shell, same pattern as Corridor Scoring's Adjust Weights modal) to copy that row's — the source's — attribute values onto one or more other compatible features. Routes and Lines share one target pool (identical attribute schema); Points and Polygons only target their own type. Copyable fields per type live in `COPY_FIELD_DEFS` (`kind: "text"|"select"|"number"|"bands"|"routearray"` drives generic get/has-value/set logic via `copyFieldGetValue`/`copyFieldHasValue`/`copyFieldSetValue`): Point — `group`, `serviceAreaType`, `_bufferRadius`, `stopId`, `associatedRoutes` (atomic array copy); Line/Route — `group`, `direction`, `mode`, `avgSpeed`, `runTime`, `service` (atomic Time Bands copy), `networkRole`, `_bufferRadius`. A field def may carry `target: "properties"` (only `_bufferRadius` does): its value is read/written on `feature.properties` instead of `properties.attributes`, and the get/has/set helpers take the feature's `properties` object. An explicit `0` radius is a real value and copies; an absent (inherited) radius is "no value to copy". After a copy that touched `_bufferRadius`, `applyCopyAttributes` calls `App.rebuildBuffersForType(type)` for every target type touched (a Line source can write onto Routes) and `App.notifyProject()`; Polygon — `group`, `notes`. **`serviceId` is deliberately never copyable** — it's the Route Costing / Trip Builder pairing key, and copying it onto other routes/lines would silently merge them into the same Service. A checkbox is disabled (with a "(no value to copy)" hint) when the source has no value for that field — blank source fields are always skipped per-target, never overwriting existing target data with emptiness. An amber `.as-copy-warning` banner (recomputed on every checkbox change) reports how many selected targets already have data for the checked fields before the user applies. `applyCopyAttributes` pushes one `App.undo.push()` snapshot for the whole batch, replicates `serviceAreaType`'s normal side effects (`App.ensurePointWalksheds()` / `App.refreshBuffers()` / `App.notifyProject()`) since it writes the attribute directly rather than through that cell's own `onChange`, then does the same cache-save/refresh/re-render as every other edit. `closeCopyModal()` is also called from the module's `onClose` hook so the modal doesn't reappear on next open if left open when the whole popup is closed.

**No new persistence:** all edits (including Copy Attributes) write through to `feature.properties` / `feature.properties.attributes`, which the session cache already serializes. The module itself does NOT register with `App.cache.registerModule`.
