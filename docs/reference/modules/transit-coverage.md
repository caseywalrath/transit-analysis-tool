## transit-coverage.js

Share of a service area's population and jobs within a buffer of selected routes/lines, optionally only those meeting a peak-headway threshold.

- **Inputs:** geography/ACS year (LODES warning), buffer distance (mi, default 0.5, module-owned via `js/core/module-buffers.js`), day type (via `App.getEffectiveServiceBands`), optional headway threshold (blank = plain coverage), routes+lines checklist, drawn-polygons checklist (union = service area / denominator).
- **Rules:** builds **private** buffers via `App.buildAnalysisBuffer`/`App.foldAnalysisUnion` — never reads/mutates `App.routeBuffers`/`App.lineBuffers`. Unions are clipped to the service area with `turf.intersect` (null = zero coverage, not an error). Population `B01003_001E` for partly covered geographies is counted by 2020 census-block population (default) or by land area, chosen in `#tcApportionMethod` (`_apportionMethod`, saved as settings `apportionMethod`; a session without it restores as `area`, so old sessions keep land area). Each of the three unions (service area, covered, threshold) gets its own fractions from `App.computeApportionFractions`; the block download is cached by geography bbox and shared. If block data cannot be fetched, that run uses land area and shows a warning line (`#tcApportionNote`); the footnote, CSV (`# Residents counted by:`) and saved `lastSummary.apportionMethodUsed` record the method actually used (an older summary without it reads as land area); jobs are whole-block via `App.fetchBlocksInternalPointsInUnion` ("—" + ⚠ without LODES).
- **Coverage from:** `#tcCoverageFrom` (`_coverageFrom`, saved as settings `coverageFrom`; a session without it restores as `line`, new work defaults to `stops`). `stops` buffers each route/line by circles (`App.buildStopCircleUnion`, plain circles at the buffer distance, never walksheds) around its associated stop Points (`App.associatedStopPoints`, matched on `routeIdx`/`lineIdx`, hidden stops skipped unless Include hidden); a feature with no stops falls back to the line buffer. A stop shared by several routes is counted once in the union. With Use Display Buffers on, display buffers are always used and this setting is ignored. Each headway row records `coverageSource` (`stops`/`line`) and `stopCount`; the results list shows "(from N stops)"/"(from line)" and the CSV adds `coverage_source`, `stops_used`. Stops outside the service area simply clip to nothing (coverage 0, no error).
- **Map:** one geojson source with `kind`-filtered layers (coverage fill, threshold fill, dashed service-area outline) + legend. Colors resolve through `App.resolveLayerColors("transit-coverage")` (categorical spec, one class per fill) at add time and in the `setData` branch; `repaintOverlay()` is registered via `App.registerLayerRepainter` (paint-only), and `fillLegendColors()` re-tints legend swatches (via `LayerPalette.rgba`) after mount and on repaint.
- **Persistence:** schema **v2**, numbers + selections only. Selections are the UNCHECKED features of both checklists as stable `{type, id}` refs (`_uncheckedRefs`), so new features default to checked and deletes/merges can't shift selection; `headwayRows` carry `featureId`. v1 index selections migrate in `restoreTcState`. Geometry is not persisted; GeoJSON export is disabled until Re-run.

- **GTFS routes:** with a feed loaded, a third checklist lists the routes running on the GTFS analysis date (hidden ones only with Include hidden; unchecked ones saved as `gtfsUnchecked` route ids). A route's stops are those with a departure of it that day (`stopServiceTable`, so a terminus with arrivals only is not counted). Buffers by mode: bus 0.25 mi, rail 0.5 mi (`busBufferMi` / `railBufferMi`; rail = route_type 0, 1, 2, 5, 7, 12); a stop on any selected rail route takes the rail buffer. The headway threshold applies per stop: the combined peak headway of the selected GTFS routes there. **Distance measured** (`distanceMode`): straight line, or along streets through `App.multiWalkPolygon` once per buffer distance (also used for drawn stops when Coverage from is stops); stops off the street network fall back to circles and are counted in a note, and with no network loaded the run uses straight line and says so. Thousands of circles are merged by `App.unionManyPolygons` (pairwise, yields between rounds; a failed pair keeps both inputs), not `App.foldAnalysisUnion`, which is too slow at system scale (RTD about 3 s for 7,400 stops). Results add one headway row per GTFS route, a "GTFS stops: N (M qualify …)" line, and the CSV `# Analysis date:` / `# Distance measured:` / `# GTFS stop buffers` lines; table rows say "stop buffers" and the footnote names the distances. Session schema **v3** (v1 and v2 load with the defaults). Test: `test/browser/transit-coverage-gtfs.test.mjs`. **Stale rules:** the run snapshot (`makeRunSnap`) is taken, and the GTFS analysis date read, before the run's first await, so a date change mid-run cannot leak into the results label. The street-network epoch is tracked only for runs that asked for along-streets distance (the epoch is stripped from `featureGeomSignature`), and the feed signature (`gtfsSig`) only for runs that used GTFS routes. A restored run does not track the network; its GTFS inputs are compared once when the feed is loaded (saved analysis date, each saved GTFS route still available) and it goes stale on a mismatch. A streets run where no street polygon came back counts those stops as off-network, so the straight-line note shows. Known gap: a restored run whose feed never loads is not marked stale.

`App._tcTest` → `{computePeakHeadway, formatPct, formatCount, buildStatSentence, _csvField}`. Test-only hook (exists only when `window.__MAT_TEST__`; used by `test/run-golden.mjs`).
