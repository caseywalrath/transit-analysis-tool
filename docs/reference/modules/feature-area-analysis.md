# Feature area analysis

Reference detail moved verbatim from `CLAUDE.md`. Read the code when this and the code disagree.

## Files

- **`buffer-summary.js`** — Feature Area Analysis module: MANDATORY_VARS, expandGroups, runSummary, buildVarChecklistHTML, and a points/lines/routes/polygons checklist. It can use a 0.5-mi default analysis distance or selected displayed buffers; polygons pass through unbuffered. Registered as popup-based module. **Feature selection by stable ID (Phase 4b):** `_state.featureFilter` is `null` (= all checked) or an array of the CHECKED `{type, id}` refs (`getCheckedRefs()`); checkboxes carry `data-feature-id`, the run-time index filter handed to the buffer helpers (`getFeatureFilter()`) is built fresh from the DOM, and the cache saves `schemaVersion: 2` + `featureRefs` (v1 `featureFilter` index filters migrate in `apply`). **Choropleth (Phase 1 of `docs/feature-area-choropleth-plan.md`):** `runSummary()` retains every fetched variable's per-geography values (`_lastGeoData.perGeo`, keyed by var code, `{level: "geo"|"tract", values: Map<GEOID, number>}` — tract-fallback variables keep their tract-level map) alongside the geometry, overlap fractions, and denominator specs needed to redisplay them — no additional fetches. A "Map by geography" dropdown (`#basMapVar`, populated by `populateBasMapVarDropdown()`) lists every displayed variable with per-geo data (tract-fallback entries labeled "(tract level)"); picking one renders a 5-class quantile Blues choropleth via `App.choropleth.render({id: "bas", ...})` colored by **whole-geography values** (clipped geometry when apportioned, uncut values — the settled design decision, so a large geography barely clipped by the buffer never reads as "low"), with a hover popup (`basHoverHTML`) showing the hovered variable plus its percent/apportioned share and every other selected variable's value at that geography, and a floating legend (`projects/choropleth-legend.html` widget id `"bas-legend"`) filled via `App.choropleth.fillLegend`. A `#basHideChoropleth` checkbox toggles visibility without re-rendering; selecting "None" removes the choropleth and restores the plain gray `census-geos` overlay. `#basStatus` (`App.renderModuleState`) shows Done/error, and a **stale-but-visible** banner with a working Re-run button when features change while results are on screen (the module deliberately does not auto-clear on feature deletion, unlike Corridor Scoring/Transit Coverage). A `clear` lifecycle hook (wired to the toolbar Clear/Reset Session buttons) removes the choropleth, hides the legend, and empties the census overlay so neither button leaves orphaned map layers. The selected map variable persists as an additive `mapVar` cache field (geometry/results are not persisted, so a restored session's dropdown re-selects and the choropleth re-renders automatically on the next Calculate Summary, matching the Transit Coverage/Transit Travelshed settings-only precedent). **Analysis depth (Phase 2 of `docs/feature-area-choropleth-plan.md`):** an **"Export by geography (CSV)"** button (`#basExportGeoCsv`, `exportByGeographyCSV()`) is enabled once a run succeeds; it writes one row per base-geoLevel GEOID (`GEOID`, `geoLevel`, `overlap_fraction`, then per displayed variable a raw-value column, a `_pct` column when a denominator resolves, and a `_apportioned` column when the run was apportioned) — tract-fallback variables get their own `_tract`-suffixed columns, looked up via the child block group's parent-tract GEOID (`geoid.slice(0,11)`, the same slicing convention as TPI's static tract fallback) and therefore repeated identically across every block group sharing that tract. A **"Shade by"** dropdown (`#basMapNorm`: Count/Percent/Density, `updateMapNormSelect()`) re-classifies the same choropleth on a derived per-geo value instead of the raw one — Percent divides by `App.getDenominator(_mapVar)`'s resolved per-geo value (disabled with a title tooltip, via `percentShadeAvailable()`, when the variable is `agg:"avg"` or its denominator — including every `$group` member — wasn't fetched this run); Density divides by the whole geography's own area in mi² (`turf.area`, lazily cached per `"<level>:<GEOID>"` key on `_lastGeoData.areas`). Both the legend title/note and the hover popup's extra line adapt to the active mode, and the choice persists as an additive `mapNorm` cache field. **LODES** variables now participate fully: `runSummary()`'s LODES branch also calls `TPI.aggregateLodesToGeo(App.lodesData, geoids, geoLevel)` (feature-detected — `console.warn`s and skips if `window.TPI` is ever unavailable at call time) to store a per-geo rollup in `perGeo` (marked `source: "LODES"`), so LODES entries now appear in the map dropdown and the CSV export with a "whole-block rollup; area apportionment not applied" note in both the hover popup and the legend; the results-notes footer adds a sentence that this per-geo rollup and the union-level LODES total above it (a different method — whole-block internal-points test) can differ slightly at buffer edges. **Styling controls (Phase 3 Step 3.1 of `docs/feature-area-choropleth-plan.md`):** two more `#basMapRow` dropdowns — **`#basMapRamp`** (Blues default / Heat / Greens / Diverging Rd-Bu, mirroring `App.choropleth.RAMPS` — Rd-Bu annotated "best for percent/deviation") and **`#basMapClasses`** (5-class quantile default / 5-class equal interval / Continuous) — feed `ramp`/`method` straight into the same `App.choropleth.render({id: "bas", ...})` call the map-variable and shade-by selections already drive; both persist as additive `mapRamp`/`mapClasses` cache fields and are re-synced onto their `<select>`s at the top of `renderBasChoropleth()` exactly like `_mapVar`/`_mapNorm` (needed because the popup's DOM slot persists across close/open within a session — see `js/core/popup.js`'s `_loadedModules` — so a restored session's choice only reaches the `<select>` once the next successful run re-renders). "Continuous" has no discrete classes to label, so the legend falls back to `basLegendLabels()`: it labels each of the gradient's own 5 evenly-spaced color stops with its point value (degenerating to 1 label when every mapped value is tied) instead of calling `App.choropleth.formatBreakLabels()`'s range-label logic, which only applies to the two classed methods. The legend note's first sentence ("Classes: quantile (5)." / "equal interval (5)." / "continuous.") is built from the active classes choice and prepended to the existing shade-by/LODES note sentences rather than replacing them.

- **`buffer-summary-popup.html`** — Feature Area Analysis popup body: vertical setup/results layout on the shared `.rf-section-row` / `.rf-settings-col` / `.rf-results-col` schema. Settings has an all-feature checklist, 0.5-mi default analysis distance, Use Display Buffers toggle, variable checklist, geography, ACS year, apportion toggle, and Calculate Summary; results has the `#basStatus` status pill, progress line, the choropleth `#basMapRow` (`#basMapVar` dropdown, `#basMapNorm` Shade-by dropdown, `#basMapRamp` Color ramp dropdown, `#basMapClasses` Classes dropdown, `#basHideChoropleth` toggle, and the `#basExportGeoCsv` per-geography CSV export button, all hidden/disabled until a run succeeds), `#basEmptyState`, table, and notes.
