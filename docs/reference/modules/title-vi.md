# Title VI

Read the code when this and the code disagree.

## title-vi-engine.js (`window.TitleVI`, not on App)

Pure calculation engine: no DOM. Uses turf and `window.App` (feature resolution only).

- `TitleVI.defaultPolicy()` → policy profile: major-change rules (route miles %, revenue hours %, span %, elimination, fare %), equity thresholds (disparate impact / disproportionate burden, in percentage points), geography level, ACS year, `apportionMethod` (default `App.APPORTION_DEFAULT`), buffer distance.
- `TitleVI.createScenario(name)` → `{ …, alterations: [], impactMethod: "service_loss_area" }`.
- `TitleVI.createAlteration(name)` → `{ name, changeType: "alteration"|"elimination"|"new_route", before, after, computed, manual: { revenueHours, spanHours, fare } }`. `before`/`after` are refs `{ featureType: "route"|"line", featureId, featureName }`; `featureId: null` = a legacy ref whose index no longer resolved. `featureName` is only the label for a missing feature.
- `TitleVI.resolveFeature(ref)` → feature by ID at use time, or null (deleted). `TitleVI.findMissingRefs(scenario)` → `[{altName, which}]` for required refs that no longer exist.
- `TitleVI.computeDivergence(before, after, thresholdMi, sampleIntervalMi)` → samples the before route (~0.05 mi), distance to after via `turf.nearestPointOnLine`; beyond threshold (default 0.1 mi) = divergent. Returns `{ alteredPct, alteredMiles, totalMiles, divergentSegments: [{startMile, endMile, maxDivergenceFt}] }`.
- `TitleVI.computeServiceChangeArea(before, after, bufferMiles)` → `{ serviceLossArea, serviceGainArea, beforeBuffer, afterBuffer }` via `turf.difference`.
- `TitleVI.computeAlterationMetrics(alteration, bufferMiles, thresholdMi)` → fills `alteration.computed` (`beforeMiles, afterMiles, routeMilesPct, alteredPct, alteredMiles, serviceLossArea, serviceGainArea, divergentSegments, revenueHoursPct, spanHoursPct, farePct`). `elimination` = before only, 100% altered, whole buffer is loss; `new_route` = after only, whole buffer is gain.
- `TitleVI.computeRouteMetrics(route)` — legacy CSV metrics, kept for backward compat.
- `TitleVI.evaluateMajorChange(policy, scenario)` → `{ triggered, ruleResults, altMetrics }`.
- `TitleVI.buildImpactedArea(scenario)` by `impactMethod`: `service_loss_area` (default), `service_change_area` (loss + gain), `full_route_buffer`, `user_polygon`; falls back to before-route buffers when no change areas exist.
- `TitleVI.fetchDemographics(core, unionGeom, geoLevel, year, options)` (`options.apportionMethod`, default `"area"` so direct callers keep their numbers) → ACS B03002 + B17001 (tract fallback for poverty at block-group level) → `{ totalPop, minorityPop, minorityShare, lowIncomePop, lowIncomeShare, geoCount, geos, apportionMethodUsed, apportionNote }`. Fractions come from one `computeApportionFractions` call shared by all four sums.
- `TitleVI.evaluateFindings(impacted, baseline, policy)` → minority (Disparate Impact) and low-income (Disproportionate Burden) findings with `diffPpt`, `exceedsThreshold`, `finding`.
- `TitleVI.compareScenarios(scenarioResults)` → rows for the comparison table.

## title-vi.js (module `"title-vi"`, no public API)

4-tab popup (Major Service Changes | Equity Analysis | Service Equity | Scenarios); DOM ids `tvi` prefix, styles `.tvi-`. Stale state uses the shared `App.renderModuleState()` in `#tviStaleWarning` (with Re-run).

- **Refs:** feature dropdowns (`buildFeatureSelect`/`parseFeatureRef`) encode `type:id`. A ref to a deleted feature shows as a selected `(deleted feature: name)` option plus a red card note, and `runAnalysis` **refuses to run** (naming the adjustment) rather than skipping it.
- **Baseline filter:** `_baselineFeatureFilter` = `{ routeIds, lineIds, polygonIds }` stable IDs (`null` = all), resolved to indices only in `buildUnionFromFilter` at run time.
- **Map:** loss/impacted fill (`tvi-impacted-*`) and gain fill (`tvi-gain-*`), cleared on new analysis and by the registered `clear` hook (`clearAll()`, run by toolbar Clear and Reset Session). `clearAll()` drops only computed output: overlay, `_results`, `_baseline`, the demographics/impacted-geometry caches and the stale flag, and resets the results/baseline/comparison panes to their empty state. Scenarios and policy inputs are kept. Colors resolve through `App.resolveLayerColors("title-vi")` (categorical, classes `[loss, gain]`, fill and outline share one color); `repaintOverlay()` is the registered repainter. There is no legend, but the `.tvi-loss-swatch`/`.tvi-gain-swatch` chips on alteration cards would lie after a recolor, so `fillSwatchColors()` re-tints them from `renderAlterationCards()` (the single choke point for all callers) and from the repainter.
- **Usage hook:** registers with `App.registerFeatureUsage` (warn) for every alteration ref.
- **Persistence:** `App.cache.registerModule("title-vi", …)`, schema **v4** (v3 added ID refs + `baselineFeatureFilter`; v4 adds `policy.lowIncomeDefinition`, `policy.serviceEquity`, `seIncludeHidden` and the last Service Equity result as `serviceEquity`, without its `geos` / `region` map geometry but with the plain-number `result.geos` rows, so the CSV still exports after a restore). v1-v3 load with `poverty100`, `TitleVI.defaultServiceEquity()` and no result. v1 adds empty `alterations[]` and maps impact method `selected_routes` → `full_route_buffer`; v1/v2 index refs/filters convert to IDs in `applyState` (unresolvable → missing ref with `featureId: null`); a standalone session-file import migrates against the live features. `collectState` must not touch the DOM before the popup has opened (it once threw there and dropped the module from autosaves).

## title-vi-popup.html

Policies tab: policy settings | alteration cards + impact-method radios. Analysis tab: baseline + equity findings. Service Equity tab: see below. Scenarios tab: scenario manager + comparison table + session JSON import/export.

## Counting residents of partly covered areas

The Policies tab select `#tviApportionMethod` (stored as `_policy.apportionMethod`) chooses how residents of census geographies only partly inside the impacted area are counted: **by 2020 census-block population** (default; a geography contributes the share of its residents living in blocks whose internal point is inside the area) or **by land area** (share of land inside the area). If the block service cannot be reached the run uses land area and the results show the engine's `apportionNote`. Baseline and scenario analysis both pass the method, so they stay comparable; changing the select marks results stale (the baseline must be re-computed by hand). Results show "Residents counted by <label>." (`#tviBaselineApportion`, `#tviSummaryApportion`) and the findings, MSC and comparison CSVs start with the same line as a `# ` comment. Saved sessions without the setting load as land area, so their numbers do not change.

## Low-income definition

`#tviLowIncomeDef` (Equity Analysis tab, Geography group beside the counting method; stored as `_policy.lowIncomeDefinition`): **below the poverty level** (`poverty100`, ACS `B17001_002E`, default) or **below 200% of the poverty level** (`poverty200`, `C17002_002E`..`007E` summed). Both `TV.fetchDemographics` calls (baseline and scenario analysis) and the Service Equity run receive it. Changing it marks the equity results stale (and the Service Equity result, through its signature); `runAnalysis` refuses to compare against a baseline computed under the other definition, like the counting-method check. The baseline and summary lines, and the MSC, findings and comparison CSVs, print "Low-income: <label>." after the counting line (`ServiceEquity.lowIncomeSpec(def).label`); results saved before the setting read as `poverty100`.

Block-group poverty rate fix (engine, `TitleVI.fetchLowIncomeValues`): the poverty tables are published for tracts, so at block-group level the tract's low-income RATE (low-income persons / tract population) is multiplied by each block group's population. Giving every block group its whole tract's count inflated low-income residents by the number of block groups in the tract.

## Service Equity tab

Scheduled trips per resident in minority and low-income areas, compared with the rest of the service area (four-fifths rule). Engine: `TitleVI.runServiceEquity` / `serviceEquityStops` (`title-vi-engine.js`) over `window.ServiceEquity` (`js/core/service-equity.js`) and `App.buildAnalysisNetwork`; this file is only the UI.

- **Inputs** (`data-input-group="service-equity"`, stored in `_policy.serviceEquity`, the fields of `TV.defaultServiceEquity()`): bus walk distance (0.25 mi), rail walk distance (0.5 mi), "Use 1/2 mile at frequent stops" with "peak headway <= N min" (15; disabled while unchecked), four-fifths threshold (0.8). "Include hidden routes and Services" is `_seIncludeHidden`, kept outside the policy. Geography level, ACS year and the low-income definition come from the Equity Analysis tab. A read-only line shows the analysis date and day type (`App.gtfsAnalysisDate`), or "No GTFS feed: drawn Services only."
- **Run:** `#tviSeRun` ("Run service equity test") calls `TV.runServiceEquity(core, _policy, { includeHidden, onProgress })`; progress and errors go to `#tviSeStatus` as plain text, an error leaves the previous result in place.
- **Results:** a Minority and a Low-income card (trips per 1,000 residents in the protected group and in the other areas, ratio to two decimals, a pill: `disparity` "Potential disparity" with the red `.pill.low`, `no-disparity` "No disparity" `.pill.mh`, `insufficient` "Not enough data" `.pill.na`; "N geographies, regional share X%"), a summary line (stops, GTFS trips + proposal trips, geographies, date) and a notes list: the network's own notes, stops with no residents in reach, skipped proposals, the half-mile count when that switch was on, the low-income definition and "Residents counted by 2020 census-block population." (the stop-to-block allocation is always by block population, independent of the counting-method select). Export CSV: `# ` lines (date and day type, settings, both findings, low-income definition), then one row per geography (`result.result.geos`): geoid, residents, trips, trips per 1,000, minority and low-income share %, minority and low-income area yes/no.
- **Stale:** derived, never latched. The result stores `signature`, a short hash of the settings JSON, geography level, year, low-income definition, include-hidden, GTFS day parts, a loaded-feed identity, the drawn Routes' and Lines' hidden flags (when include-hidden is off), `App.gtfsAnalysisDate.get()`, `App.gtfsScopeRouteIds(includeHidden)` and `App.featureGeomSignature()` (road-network epoch removed: the test walks in straight lines). It is taken before the run's first await. `refreshSeStale()` compares it on every input change, on `update()`, on a date change (`App.gtfsAnalysisDate.onChange`, registered in `init`), when the tab opens and when the popup opens (no GTFS hook exists for day parts or route hiding, so those show on the next of these events), so reverting an input clears the banner. A restored result whose feed is not loaded yet reads as stale until it is. Banner: `#tviSeStaleWarning` through `App.renderModuleState` with Re-run.
- **Clear:** `clearAll()` drops the result, bumps a generation counter so a run still in flight is discarded, and resets the pane; the settings stay.
- **Test:** `test/browser/title-vi-service-equity.test.mjs` (hand-calculated numbers in its header).
